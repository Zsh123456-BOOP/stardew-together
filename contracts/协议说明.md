# 本地工具协议 v1

基础地址默认 `http://127.0.0.1:18765`。除 `/health` 外均要求 `Authorization: Bearer <本地令牌>`，令牌由启动脚本生成并保存在忽略提交的 `.local.json`，不能记录到评估报告中。

## 感知

- `GET /health`：就绪状态、适配器状态、当前会话 ID、协议版本。
- `GET /state`：当前地图、时间、玩家位置、机器人位置/背包/工具/能量、作物可浇水与可收获状态。
- `GET /map?actor_id=bot-1`：地图尺寸和该机器人可通行的格子，包含动态物体与其他机器人的占用。

地图与角色来自游戏内对象，不分析屏幕。首版只控制玩家当前地图中的机器人。

## 执行

`POST /commands` 示例：

```json
{
  "session_id": "当前会话",
  "command_id": "每条命令唯一的 ID",
  "actor_id": "bot-1",
  "skill": "water",
  "target": [48, 18]
}
```

游戏端低层白名单为 `step`、`water`、`harvest`。目标必须是机器人当前格的上下左右相邻格。`step` 正常移动一格；其余动作由机器人面对目标后执行。

- `GET /commands/{id}`：查询 `running/succeeded/failed/cancelled` 和前后状态证据。
- `POST /commands/{id}/cancel`：带当前 `session_id` 请求取消。单格动作会先到达安全边界；如果已经完成，仍返回 `succeeded` 和 `cancellation_requested=true`，不能把已发生的效果说成撤销。
- 同一命令 ID 和完全相同的请求体重复提交，返回原执行记录，不再次执行；同一 ID 配不同请求体返回冲突。
- 加载存档、回到标题或重置测试场景会更新会话。旧会话写请求被拒绝。
- 网络错误或超时后先按原命令 ID 查询，不直接用新 ID 重放。

结果校验：

- 移动：最终格子和像素位置均到达目的地。
- 浇水：真实 `HoeDirt` 状态变为已浇水。
- 收获：作物不再可收获，并且相应产物数量在该机器人背包中增加。首版仅支持普通手摘作物，收获通过原生掉落与机器人拾取完成。

动作派发和状态读取都在游戏主线程进行。HTTP 线程只接收和排队。队列限制为 32 个请求，每帧最多处理 8 个请求。等待主线程超时返回 504，可能已经开始的写请求仍需按 ID 对账。

## 测试场景

`POST /lab/reset` 需要当前会话，并且仅在 `--lab` 启动、单机 AgentLab 角色、没有运行中动作时可用。它初始化测试地块、作物、机器人和工具，之后更换会话 ID。

这个接口是测试夹具，不是 Agent 的日常工具；初始化不计入正常任务成绩。正常任务工具不提供传送、改物品数量或直接改作物状态。

## Python 高层工具

- `move_to`：A* 寻路和逐格移动；已确认的移动失败可触发有限次数重规划。
- `water_area`：读取区域内需浇水的真实目标，寻找交互站位，执行和复查。
- `harvest_area`：筛选成熟作物，收获并检查入包。
- 持久化任务：计划、步骤、控制请求、动作前后证据和失败原因存入 SQLite。
- 暂停/恢复：在动作完成边界停止派发；恢复后重新读状态，跳过已完成目标。

Python 负责确定性的技能执行，Codex 目前充当上层规划者。尚未接入独立运行的 LLM 服务，也尚未封装 MCP。
