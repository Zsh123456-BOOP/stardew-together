# Agent 原生工具与经营决策优化复测

本轮按用户“开始，然后重新测试”落实五项优化，范围为独立新档正常时间一天；不改动旧测试窗口或个人存档，不部署到服务器。

## 实现与边界

- 原生 Tool Calls：AutoplayModel 通过 API tools 提交当轮工具，读取 message.tool_calls；点号映射为双下划线，执行器仍使用原业务名。整轮先校验调用数、已加载工具、唯一 ID、完整参数 JSON 与明确的参数类型，再执行。API 工具 schema 从 Catalog 的参数短写生成；有歧义的字段保留原契约并继续使用现有业务检查，未启用 DeepSeek Beta strict，不能宣称服务端保证所有参数正确。
- 只保留上一轮完整 assistant/tool 消息对，按 tool_call_id 关联。查询回执引用原始 result_id；异步动作只回传排队/接收状态，实际完成在后续原生回执确认。取消、查询依赖草案明确标记未执行；陈旧回复不落地，不产生已执行回执。完整 HTTP 请求体、回复体仍归档，不含认证头。
- 仓库：常驻 assets 明确列出原生共享箱、容量和建设目标状态。storage_expand 在现有可达仓库能够容纳待存物品时返回已具备能力、completed=0，不再建第二个目标；明确 additional:true 可追加。仓储政策复用已有在建仓库目标。真实容量缺口需备料时报告目标 ID 与尚未完成，而非创建后只返回笼统失败。
- 采购：排队的 player.buy 在未开商店且可从原生数据确定唯一目的地时，复用 player.procure 完成到店/开店/现场核价。必须已有明确数量、最高单价、预算、现金保留；不替模型补预算或报价，不改非金币交易，不删除显式 after 依赖。原样保留每个限额；实际消费仍走原生商店。
- 独立顺序：提示明确 sequence_after 用于顺序，after 只用于真实依赖。上一轮两条社交取消来自模型显式声明依赖购买，并非执行器能擅自删除的依赖。本轮不篡改这些显式业务关系。
- 清理：缺少活动订单的 work.run cleanup 在派原生动作前返回结构化阻碍和 farm.cleanup 入口；不擅自替模型授权清理范围。
- 劳动与现金：常驻 labor_budget 展示今日待办保守估算、剩余体力、下个晴天现有作物的手工浇水估算、自有未种种子、新地块基础锄地浇水成本。报价与布局也携带同一依据。扣除已观察洒水器覆盖，不假设次晨满体力、未知天气或未兑现收入；不新增隐性预留或种植上限。
- 上下文：去除无决策价值的空地坐标示例；当前任务进度已在 progression，不再每轮建议 progress.read；选种候选直接提供 farm.select_seeds，而非要求重新读取自身。相同查询与完整当前字段去重，合并同批相同回执，删除重复进度变化正文及配方说明。assets、labor_budget 受预算保护；原始证据仍可回读。
- 度量：原生工具 schema 与上一轮 tool_calls 都计入输入字符，避免把提示词移入 tools 后误报节省；API token 始终使用实际 usage，包含陈旧回复和重试。
