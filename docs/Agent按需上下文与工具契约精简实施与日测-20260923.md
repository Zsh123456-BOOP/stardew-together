## 3. 已实施的改动

- 成就按已核实的同指标系列展示下一档；收入、鱼种、总钓获、不同好感阈值分别处理。晨间/进度变化供给短候选，已选成就的实际进度常驻；`progress.catalog` 支持 summary/detail、series、next_only 和分页，完整条件仍按ID查询。未知规则不伪造依赖，不主动授予进度。
- 当前建设目标保留必要配方材料，不附带未选配方、建筑及高阶成就。候选与目标通过 `prerequisites.facts` 共用材料事实；未选采购阶段收起完整种子报价表，保留相关店面窗口和补读入口。库存、照料负担、当前任务、失败及承诺继续提供。
- 采购effect增加品质，日记依据同一command_id内的品质、数量和费用关联，只归并准确匹配的衍生入包/扣款。保留支持证据、真实批次和不匹配的变化；默认只发送当天紧凑事实，原始记录归档。V2实机中，6份花椰菜种子/480金与1份防风草种子/20金各只出现一个购买事实，未再重复发送对应入包与扣款行；batches表示原生事件批数，不等于采购订单数。
- 每个请求冻结ToolSpec，API发送与整批Decode（含计划内动作）共用Schema。work.run的参数与说明改为结构化配置，Catalog文本也从它生成；农务/资源/仓储直接可用，钓鱼/矿洞/畜牧/伙伴生产按任务或lookup展开，活动任务保留配置。补全原来藏在正文中的参数，并检查未加载的goal、已知但未加载的参数及角色错配。
- 数组枚举和开放模式说明进入Schema：例如work_profiles明确列出farm/resource/storage/fish/mine/animals/production，cleanup的scope描述保留道路、田地与zone格式。删除等价的空required、空properties与additionalProperties:true；默认仍允许扩展属性，未偷偷切换严格协议。保留_plan参数声明。
- context.read支持一次读取1–4个section。查询使用规范化参数和新鲜内容版本归并，命中仍返回实际内容。此memo先重读相关原生域，**不承诺减少原生读取或模型调用**。最终10条已执行查询版本记录没有同内容重复命中，尚不能宣称缓存带来了实测收益。
- 归档每次发送前冻结视图、字段内容版本及工具配置；报告记录请求模型、返回模型及fingerprint，未返回则保持缺失。精简中文与重复系统规则，未将英文翻译自动当作token收益。
- 启动器支持独立XDG配置/存档目录和加载已有AgentLab存档；未在旧窗口热换DLL，未注入物品、现金、时间或游戏进度。
