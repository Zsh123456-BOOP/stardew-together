# Agent 按需上下文与工具契约精简方案

后续：本方案已实施并完成同档日测，见 [实施与日测记录](Agent按需上下文与工具契约精简实施与日测-20260923.md)。下文保留开工前的设计与目标，不代表全部数值目标已达成。

日期：2026-09-23。状态：方案，尚未修改运行代码或启动新游戏测试。本次完成代码复核和中英文离线分词小实验；下面的接口、预算与验收线均为拟议设计。

建议采用：**常驻当前事实，变化时提示发展方向，AI选中后展开；先减少无关信息和重复表达，再按实测决定语言。** 不新增每轮分类模型，不更换原生执行器。保留自主选择发展方向、预算、种植规模的权力。

## 1. 依据与需要纠正的实现

最近完整一天为 `ee000f4`，run `1daefea1fbee41a187d236807ebe3438`。45次请求平均30,840字符：当前上下文15,057、工具定义12,901、system 1,835、上轮消息1,047；输入token中位数11,122、全天510,640。第一轮压缩后的完整一天为29次请求、输入中位数9,967、全天284,755，后续应同时对照它，不能只对照最初失败样本。

代码复核发现：

- `MemoryContextRuntime.TaskPrerequisites()` 每轮取未完成成就前三项；`CapabilityCatalog.ReadNativeGoalRows()` 按ID排列，导致15k/50k/250k收入成就反复出现。这是目录顺序，不是按当前任务选择。
- `ContextBudget.Protected` 保护整块 prerequisites、operating_candidates 等内容，memory降级又完整保留daily_activity。软预算因此无法精确控制真正可以省略的部分。
- `NativeToolProtocol.Shape()` 从Catalog长字符串提取参数。`work.run`的stock_target、cleanup_id、additional、exact_quality、start_level、region、travel_budget等有效参数仍藏在正文里；直接删段落可能同时删掉合法调用依据。
- 代表请求20个工具共12,720字符，11个基础工具占7,331；work.run与plan.submit合计3,967。必须处理基础大工具，继续只删除外围工具收益有限。
- native history仅保留上一组调用/结果。服务器“缓存过”或历史result_id存在，不代表模型在本次输入里仍看得到事实。

## 2. 成就：每条路线下一档，按需展开

成就不再作为每轮默认明细。信息供给采用下表，已选目标与到期承诺不受候选数量限制。

| 何时 | 模型收到什么 | 何时展开详情 |
| --- | --- | --- |
| 普通执行决策 | 当前目标、下一必要条件；没有相关成就则不带成就明细 | AI明确查询或选择该目标 |
| 晨间、目标完成/受阻、季节窗口、原生解锁变化 | 少量跨方向的简短候选；每条同指标成就线只给下一档 | AI挑选其中方向后 |
| 已选定成就 | 该成就实际进度、下一前置、时限/资源缺口 | 需要配方、缺项清单或证据时 |
| AI查看完整目录 | 筛选、分页的简表 | 指定ID后返回完整条件和证据 |

收入线示例：`累计原生收入 0/15000，后续4档可查询`。达成后切换至50,000档；普通回合无须同时发送15k/50k/250k的完整definition。若AI未选择这条线，晨间给简短候选即可。

不能把全部成就串成一条路线：收入、委托、料理、制造、鱼类收集可以并行；鱼种数与累计钓获数不是同一个指标；不同好感阈值和人数也不能混合排序。仅对**同指标、同统计口径、门槛递增**的系列折叠展示。展示下一档不等于宣称后续档在游戏中锁定；实际依赖只认已核实的原生条件。未适配规则保留unknown，不能按编号猜先后。

复用已有 `progress.catalog`、`progress.dependencies`、目标跟踪入口，统一 `TaskPrerequisites` 与 `ProgressionRuntime` 的成就选择策略。拟给catalog增加summary/detail、series、next_only等视图参数；这些参数目前不存在，实施时需同步Schema与校验。完整目录仍可发现，跨线探索仍可主动请求。

同时取消“每一轮都检查主线、任务、成就并选一个发展前置或解释暂缓”的强制提示。晨间评估融入当天第一次决策，避免额外付费轮；关键变化时重新评估，防止长期只做日常而忘记发展。

## 3. 状态：每项事实只保留一个权威位置

每次请求保留当前决策能够独立理解的短状态，而不是只发送自上次以来的差分。

| 内容 | 常驻内容 | 按需或条件触发内容 |
| --- | --- | --- |
| 角色与库存 | 时间、地点、体力、现金、实有物品、必要工具能力 | 完整物品用途和历史存取明细 |
| 农务 | 当前作物/干地、已批准布局、自有种子、今日及下个晴天负担 | 完整地块、清障目标、布局候选 |
| 当前任务/承诺 | 实际状态、必要依赖、已保留资源、失败条件 | 已结束任务的完整轨迹 |
| 设施与目标 | 真实设施及当前建设目标状态 | 无关配方、建筑总目录 |
| 发展前置 | 已选目标的下一前置；未知仍明确未知 | 随手附带的围栏、道路、收入成就和小屋条件 |
| 商店 | 当前目的地/订单涉及的开放窗口和报价有效性 | 所有商店营业表；未选购方向的完整商品表 |
| 候选工作 | 简短可选方向、价值依据、关键缺口 | AI选择扩种后再给相关报价比较 |
| 回执 | 本次新结果、实际数量、失败原因、ID | 大段证据与执行器内部过程 |

具体合并：箱子材料缺口只在所选目标事实里一份；候选引用实体ID。任务进度只在任务区一份；工具携带状态只在库存区一份。时间/地点由共同快照头提供，真正历史事件仍保留自身时间。

报价不能裁掉决定是否值得采购的依据。未选择交易时，只给“可到种子店比较扩种”及必要窗口、资金/劳动边界；选定交易后，给足当前相关作物的价格、生长/季节约束、现金和劳动预算。全量商品目录按需分页，现场价格与购买限制仍执行原生复核。

`ContextBudget` 从“整块不可裁剪”改为保护具体必要字段：当前事实、活跃任务、真实失败、预算/承诺、紧急窗口和未交付结果不能丢；目录、原始规则正文、重复说明、未选备选项可裁。空数组可按契约省略；业务未知不得伪装成空集或零。

## 4. 记忆：同一事实的一次表达

日常记忆示例：`已购买防风草种子15份，支出300；已种30株、浇30株；出货未结算0。当前种子数量见inventory。`

把一次采购的“购买15”“入包15”“现金-300”归为一个有来源的交易事实；当前库存独立来自原生读取，不从流水累加。实施时在原始receipt/typed effect处保留command_id与来源关联，袋内和现金差分作为支持证据。现有按天聚合行已丢失部分因果关联，不能仅凭数量相等就去重。

未被交易解释的现金/物品变化必须保留为独立观察，避免丢掉赠送、补给、掉落等。真实两笔购买不得合并成一笔；仓储转移不是收入；收获地块数不是产物数；待结算出货不是已到账现金。相关失败、承诺、季节限制继续常驻，完整事件与证据留在原始归档。

## 5. 工具：结构化契约，再按能力配置提供

保留业务工具与原生执行器，增加统一结构化ToolSpec作为参数、默认值、角色、能力配置和必要约束的来源。API定义生成与Decode使用**同一请求冻结的配置**；回复落地后再按实际游戏状态检查执行条件。

work.run分为农务、资源、仓储、钓鱼、采矿、畜牧、伙伴生产等能力配置。本轮若需要农务与备木材，只提供对应goal枚举、参数和说明，以及共用预算/原生证据规则；不再同时携带火山、骷髅矿、动物和伙伴流程。配置由实际角色、当前任务/目标、机会及AI明确lookup请求共同决定，不按日期一刀切。

有说明的goal才进入本轮可调用枚举；未加载能力不能靠隐藏参数偷偷执行。AI通过tools.lookup扩展，下一轮收到相应完整配置后再决定。活动任务及其依赖涉及的配置持续保留；明确切换或完成后回收。不能仅依赖三轮过期，导致尚在使用的工具突然失去参数说明。

先补齐正文里的合法参数，再迁移到结构化定义。不能在此时直接把additionalProperties改成false，误伤老调用；字段收紧需独立回归。保留参数类型、必填字段、价格/数量/品质含义、after与sequence_after差异以及零副作用拒绝。

`plan.submit`不内嵌全部业务工具Schema，只保留通用任务结构，内部args按本次对应业务契约交叉校验。普通单项工作复用已有高层任务；多步计划需要时加载plan.submit，是否移出常驻集由回放中的额外lookup成本决定。活跃队列保留取消/查错入口。前轮移除_plan参数提示曾造成伪工具调用，保留其短属性，不重走同一个失败尝试。

稳定的配置、参数次序与共用前缀有利于缓存，但缓存收益另行统计。服务端缓存不是会话记忆，不能代替实际发送模型需要的内容。

## 6. 语言：等义比较，择优采用

英文每字符的token通常较少，但同义英文可能需要更多字符。JSON键名和工具名本来已是英文，翻译只能影响自然语言说明。应分别比较“原中文/等义英文”和“精简中文/等义精简英文”，避免把删减收益算成语言收益。

分别使用官方DeepSeek-V4-Flash与DeepSeek-V4.1-Flash分词器，对4条当前真实description与人工忠实翻译离线计数，均关闭自动special tokens；两版在这组样本上的结果完全一致：

| 说明 | 中文token | 英文token |
| --- | ---: | ---: |
| context.read | 23 | 24 |
| player.travel | 19 | 20 |
| agent.wait | 12 | 15 |
| player.sleep | 96 | 123 |
| 合计 | 150 | 182 |

这组英文多21.3%，不支持“一律换英文”。短农务配置等义示例为中文110、英文125；它仅是方案示意，并未覆盖当前全契约，不能把它与完整work.run的差额直接算作等义压缩收益。样本数较少，不代表每句话或所有模型都会如此。

采用清晰短句；参数/ID保持英文和原生值；说明按同义文本实测择优。避免中英双份常驻、极端缩写、删去默认值或重要边界。若后续采用英文工具说明，同步调整CLAUDE.md的中文说明约定；面向用户的报告仍用中文。

离线计数只是文本实验，不是API完整请求计费或行为质量验证。当前代码用UTF8字节/2估算预算，也不能作为精确tokenizer。以官方适配分词器辅助校准，最终以实际API usage对账。

## 7. 按需读取不能制造更多请求

关键策略是主动提供够做下一步的短事实，避免反复要求“读完所有省略字段”。选定阶段一并加载相关事实与工具，例如选扩种时同时给报价摘要、种植负担和可用采购工具。

查询按tool、规范参数、相关领域revision缓存；库存变更不应让静态成就目录全部失效。若事实已在本次输入，回指其位置；若本次不含该事实，必须补回简短内容，不能只回not_modified/result_id。允许一次读取几个确实相关的section。

仍保留完整且成对的assistant/tool反馈，错误明确未执行、指出合法参数和修复入口。相同条件下重复查询先修事实供给、触发原因和失效规则，不硬性限制查询次数，也不自动重放先前动作。

复用现有忙时延迟模型请求机制。需要主模型处理的只有新取舍、报价选择、执行失败、重要变化、菜单分支等；已覆盖的劳动继续交执行器。缓存一个查询结果只减少读取工作，不自动减少付费模型轮数，报告必须分开统计。

## 8. 实施顺序、预算和验收

分阶段提交并分别验证，避免把全部变化混到一次实验中：

1. 成就/配方/建筑按需、取消每轮发展检查、按具体字段保护预算；制作当前状态与候选的统一事实引用。
2. 交易流水因果归并、记忆短摘要、按决策阶段加载报价/服务窗口；补领域revision和重复查询统计。
3. ToolSpec迁移、work.run能力配置、请求与解码共享契约；评估plan.submit等常驻入口。
4. 做语言等义实验和共用规则去重，保留低token且行为无回退的写法。
5. 同一起始存档的完整一天配对测试，记录全部重试和中断；结果不好时按阶段定位，不再另开随机新档挑最好的一次。

首轮设计目标：常规决策API输入中位数6,000–8,000 token；工具定义token降低30%–40%；输入字符约14,000–20,000仅作参考，不能替代token验收。复杂报价、原生分支和必要失败证据允许超出软预算，并记录原因。这些都是待验证目标，不是已实现收益。

同档日测除对比最新45次/510,640输入，还应争取不高于较好的旧版29次/284,755输入水平；旧版非配对数据仅作历史标尺，正式改善结论以重新配对对照为准。不能为了省token提前睡觉或少完成工作。对照时固定模型配置、正常时间、开始存档和运行目标，并记录供应商返回的model、fingerprint和当时别名映射；云模型未提供不可变版本时说明控制范围。

| 验证 | 必须检查 |
| --- | --- |
| 离线投影 | 45份已发送请求逐块统计；活跃目标/库存/错误/承诺不丢；旧合法调用仍有对应参数依据 |
| 回放范围 | 旧请求是已经压缩的视图，不是完整原生快照；不能靠它证明旧版省略信息的可发现性。新测试另保存发送前冻结视图及版本 |
| 成就定向 | 同线跨档、多个独立系列、未知条件、已选长线目标、季节/限时目标不被隐藏 |
| 记忆定向 | 两笔相同交易不误去重；未解释差分保留；仓储/出货/种植计数不混淆 |
| 工具定向 | 参数补全、角色隔离、lookup后可调用、活动任务配置不失效、未知批次零副作用 |
| 查询定向 | 同revision重复查询；缓存内容未在本轮时仍可读；原生状态变更后及时失效 |
| 模型质量 | 参数错误、直接拒绝、修复调用、事实矛盾、跨领域机会是否漏掉 |
| 完整一天 | 正常保存、睡前农务、原生收入/支出与资产、有效劳动、睡觉理由；未到收获日不推断长期利润 |
| 实际成本 | 全部输入/输出/cache hit/miss、总请求与查询、总延迟；不只报告单次中位数 |

先过纯函数/契约回归，再做隔离原生预检和完整一天；不在用户旧窗口热换DLL。成就/目录选择应仅观察原生状态，不主动授予进度。
