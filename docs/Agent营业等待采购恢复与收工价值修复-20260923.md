# 营业等待、采购恢复与收工价值修复

## 触发与证据

用户观察到第一天种完初始种子后站立等待、采购后再次要求采购、有体力和未播种种子却收工。实际运行 `26af5c7d1d904353afe7f510a15ec5a5` 的日志显示：

- 07:40–08:30 是查询与错误调用循环，未调用 `agent.wait`；查询已给出种子店 09:00 开门，但下一轮常驻 `service_hours` 被筛为空。
- 09:40 买入 10 份防风草后，播种工作回程在 SeedShop 出口附近发生 `no_path`。后续买入 4 份土豆，重复购买 10 份防风草的请求被资金检查拦截，并未重复扣款。
- 11:00 收工评估接受了“种植没有即时回报”的理由。模型仍有约 202 体力、14 份未播种种子；旧候选白名单排除了规划/播种，`low_value/defer` 仅检查短说明是否存在。

原始诊断与完整输入输出保留于忽略目录 `work/decision-review-trial/diagnosis/`，不提交运行数据。

## 实现

1. **营业时间保留。** 两层上下文压缩均保留各已知商店的紧凑时间事实，包括 `recheck_at`；删除重复说明，不再按“当下有可执行候选”过滤营业窗口。未打开商店菜单时，`shop.read` 区分尚未开门、不在店内、店内菜单未开、当日窗口不可用，并返回下一步前置条件。连续无原生进展的轮数与行动/有界等待提示进入常驻上下文。
2. **采购状态独立。** `FarmInvestmentPolicy.Purchase` 持久保存已批准、原生已买和回执去重；报价更新只更新报价，排队不扣减采购授权。新增 `purchase_status` 分别显示待买与实际未播种库存。当天追加选品保留已经发生的交易；重复买入超出剩余额度时，必须用 `additional_reason` 显式说明追加用途。检查位于实际工具执行入口，直接调用与排程均适用。
3. **中断后重新规划现有种子。** 已失败的播种方案不再作为同一个可直接重放的工作候选；返回农场/重新规划已有种子的候选保持可见，未买部分保留在采购状态里。不强制买满原来选择的数量，产能规划仍可缩减。
4. **收工与普通决策共用候选。** 移除收工工具白名单；待照料、待播种优先，询价与选品合为同类，保持最多三项。播种总成本尚未核实时明确为未知，不冒充零体力。`low_value/defer` 要比较今天行动和推迟的未来价值；对已有种子核验实际数量及新增购种支出为零，并要求说明生长代价。仍允许有依据地暂缓，不硬编码播种数量或睡觉时间。
5. **经营提示词。** 明确比较未来净收益、生产能力、成熟延迟、照料负担与机会成本；现金属于流动性，不是全部资产价值。模型收到持续经营目标，一天停止仍由原生过夜计数控制。
6. **窗口与声音默认值。** 按用户补充要求，项目启动器默认 1280×800 窗口、四类声音为零。隔离配置的启动偏好在游戏进程启动前写入，桥接模块在启动及读档后重新应用；不修改源存档 XML。启动器读取原生窗口/音量状态，验证后才开启模型。
7. **狭窄回程。** 在格子中心碰撞检查失败时先尝试已有的像素级真实碰撞路径；局部搜索冷却按目标格区分，避免上一格绕行刚结束就禁止检查下一格。仍由原生 `MovePosition` 移动，不改坐标、不穿透碰撞。
