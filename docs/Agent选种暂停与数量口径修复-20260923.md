# 选种暂停与数量口径修复

## 已核对问题

上一轮 `fe696a76ba33464f8e6e2e5c89432511` 在第一天 13:00 暂停。原生木材库存为 1→53→55：第一段砍三处树木获得52份，第二段清两根树枝获得2份。“实际只砍了2”是模型对最后一段的含糊叙述，不是全天产量。第二段同时给了 `count=8` 与 `stock_target=55`，旧代码静默优先后者，与说明中的二选一约定不一致。

商店不动来自三次 `seed_reselection_requires_additional_reason_review_owned_and_remaining`，其中第二次 `items=[]` 明确不采购仍被拒绝。第三次触发全局暂停和时钟冻结。旧检查把“此前买过”当作全部后续选品必须填写第二个理由的条件，属于上一轮引入的回归。

最终实际 API 输入已有木材55、树液18、24株防风草、下个晴天预计浇水48体力。模型仍误读物品、未来照料和空槽与可堆叠数量的关系。输入事实存在并不保证模型理解正确。原始诊断保留在 `work/operating-recovery-trial/diagnosis/`。

## 修改

- 选种统一使用 `reason`，删除 `farm.select_seeds.additional_reason`。有效新报价与无活动采购链时，空清单可以拒绝，新清单可以明确追加；已接受的报价不可重放，重新现场读报价才能再次选择。交易账本保留已买数量，直接 `buy/procure` 超出未履行额度的重复采购检查继续存在。
- 报价、选品及采集数量冲突归为可修正错误，回执直接提供修改方式。三次采购错误后，仅在执行器空闲、无待领取商品、菜单可关闭时退出当前商店，使独立活动恢复可见；不购买、不强制睡觉、不冻结整天。原生证据失败等严重问题仍可全局暂停。
- 同时给正数 `count` 和 `stock_target` 会在劳动前明确拒绝；只给 `stock_target=55` 且已有53时需新增2份，只给 `count=8` 则需新增8份。
- 原生资源回执标明 `completed` 是处理目标处数，`gained` 是新增物品份数。HUD分别展示真实新增/目标数/背包库存与“AI计划”；暂停时优先显示实际暂停原因，打开商店也不会强制折叠暂停详情。
- 真实报价增加按原生可堆叠规则计算的 `bag_only_max`，与现金、库存上限分别展示。此值为单独购买该品种时的可装份数，多品种仍共享空间，实际组合照旧由原生容量规划核验。
- 地里作物提供原生种子名称；照料信息明确今天已浇水不代表下个晴天免浇水。提示词要求按物品名称、单位及未来照料字段判断，不能保证模型不会继续产生推理错误。
