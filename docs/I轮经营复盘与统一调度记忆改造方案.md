## 3. 根因：共享队列还不是统一规划

`TickAutoplay` 中日常维护、经营、协作、投资、清理、目标自动化分别推进；多个模块直接向同一队列提交动作。队列能串行并不代表这些模块理解同一个目的。

典型链条：模型准备去海滩 → 一个子步骤结束 → 清理模块认为玩家可用，派返Farm → 回农场后才发现应让位生产 → 又去海滩。另一方面模型也会重复提出系统已经完成的农务或已达标材料。

`QueueLegacyAction` 把模型动作转为任务时不推导店铺营业时间，`not_before` 默认600。计划文字写“9点再去”，不能阻止6点实际派单。工具访问拒绝又混合营业、关系、路线等原因，模型只能猜。

改造要求：**模块只提出需求，一个调度器负责决策约束、合并、排期、执行和反馈。**保留现有原生动作、寻路、库存和布局算法；替换多处各自派单的边界，不另写第二套平行系统。

## 4. 记忆现在到底怎样工作

| 当前部分 | 实现 | 缺陷 |
|---|---|---|
| 当前上下文 | 最新原生状态、上一轮自由文本plan、最近工具结果、任务回执 | plan仍承载很多未结构化判断，错误可被反复续写；不是整个历史对话持续留在模型里 |
| 近期摘要 | 最近4天成功/失败统计、最近2季统计、最近6条失败、最多8项目标和承诺；最近6条工具结果和近期任务回执 | 统计没有推导店铺可用时间；只取最近几条容易让关键限制被无关事件挤出 |
| 长期归档 | 按存档检查点保存事件；`memory.search`按关键词/别名匹配，逆序取结果，单条最多4000字符，可取后续证据 | 没有按当前任务自动检索；模型计划和事实一起被检索；最新不等于最相关、最可靠 |
| 失败冷却 | 键含角色、工具、完整参数和位置前置；条件hash含位置、体力、背包、对象、NPC位置等；首次20游戏分钟，最长120分钟 | 同一家店换工具或参数成为新失败；无关状态变化解除拦截；时间到允许重试，并不等于店已开门 |

实际证据：春4 06:30唯一一次搜索 `SeedShop 开门 营业 采购 失败`，第一条返回当前模型刚写出的decision，其中仍建议“先去镇里等或用procure重试”；第二条才是原生采购访问拒绝。该检索会把模型自己的猜测再次送回去。不能把decision当作世界事实或已验证经验。

原始归档和存档检查点有保留价值，**复用它们，但重做决策记忆与失效规则**。不通过增加全量历史、引入向量库/BM25或换昂贵模型解决这些确定性问题。

### 4.1 目标记忆结构

1. **事实账本**：店铺开放条件、鱼竿是否持有、真实任务进度、配方解锁、库存、设备等。每条有主体ID、来源、观察时间、适用条件和失效依据。新原生状态优先，旧库存只作历史。
2. **执行计划**：目标、目的、父任务、已完成量、剩余量、角色、地点、营业窗口、预算、下游容量、资源预留、当前阶段。保存结构化计划，模型plan只是说明文字。
3. **可操作经验**：失败原因类别、影响的目标、仍缺的条件、何时/何种变化可以重试、验证办法、替代活动、原始证据ID。
4. **经历与关系记忆**：共同经历、人设和承诺独立保留；不能覆盖经营事实或绕过动作条件。

闭店例子：主体 `shop:SeedShop`，结果 `closed_until`，本次适用日期及实际开放时刻，受影响行为为采购/进店；只有时间进入有效窗口或真正改变开放条件时解除。玩家移动、血量变化、NPC在别处走动不解除该限制。未读清具体条件时标记 `access_reason_unknown`，只允许一次低成本条件诊断，不反复跑门口。

不同失败分别处理：

| 原因 | 允许重试的真实变化 | 不应触发重试的变化 |
|---|---|---|
| 今日闭店/未开门 | 到达下次有效开放窗口，或相关解锁/内容条件改变 | 改采购数量、换travel/procure、玩家走几格 |
| 容量不足 | 实际可用容量满足本次作业要求 | 仅调用一次没有移动物品的store |
| 材料缺口 | 可消费库存或预留方案改变 | 时间过去、对话改写、换工具名 |
| 动作阶段故障 | 原生执行器完成恢复并通过状态核验 | 换地图后假定故障好了 |
| 空区域/无目标 | 目标生成、日期刷新或到达不同的有效区域 | 改8个为3个、减少体力储备 |
| 到达用户设定截止 | 下一个获准作业窗口和剩余量 | 将其记成地点永远不可用 |

### 4.2 检索与压缩

- 调度器按当前目标、对象和地点自动提取相关约束；关键阻碍不依赖Flash主动调用搜索。
- 从原生ID建立中文/英文别名映射，例如商店名与地点名归到同一主体；检索先主体ID与原因类型，再关键词，不需要重型检索服务。
- 原生事实/动作结果优先；明确排除当前请求的decision作为事实候选。旧计划只在恢复承诺时读取，并标为未执行意图。
- 合并同一主体的重复失败为一条“次数、最近证据、下次有效重试条件”，不用向模型重复发送完整背包前后快照。
- 日/季摘要保留成果、支出收入、能力变化、有效阻碍、未兑现承诺及证据索引；成功失败次数仅为统计附件。
- 正在执行的目标、预算预留、时间窗口、归属要求、未解决阻碍不得在压缩时丢失。过期事实按条件重验，不能用统一TTL随意放行。
- 每次决策包包含当前事实差量、当前安排、相关记忆、少量可行替代方案；记录“召回了什么、为什么召回、阻止了什么”。模型仍可主动查百科和归档。
- 移除与本轮数据无关的具体库存示例，避免与真实数量混用；这是风险控制，尚不能断言某条示例就是本轮幻觉的根因。

## 5. 统一调度和一天的正确流程

### 5.1 唯一派单入口

各模块输出 `WorkProposal`：目的、完成证据、前置条件、时间窗口、位置、估算路程/时间/体力、资金物资、可用角色、预计收益或解锁价值。一个调度器筛选、合并、占用预算和派发；模型只在经营取舍、目标变化或无可恢复路径时作决定。

同一项目阶段只允许一个有效执行实例。例如去SeedShop补种子，不因模型换一种说法或后台投资模块再次发现缺种子而另派一次。

持续安排包括：准备 → 前往 → 正式作业 → 拾取/卸货 → 续作 → 交付/完成。补水、食物和存箱是子任务，完成后回原作业地点及剩余量。计划执行中，可选清理不能抢占；危险、到期必要农务等明确高优先级事件才可中断并保存恢复点。

### 5.2 确定性计算由程序完成

- 店铺按原生条件计算能否去、几点到、可以买什么及可购数量；预算不够时算出可买数量，不让模型猜商品ID。
- 库存预留按已选生产、播种、任务、总补给需求统一计算。去钓鱼/下矿前根据产物种类估计容量，允许有明确目的的提前卸货。
- 食物按本次出行需要恢复多少体力/生命决定种类数量；不再每种鱼一律留2个。任务/稀缺生产材料保护仍有效。
- 各动作共享同一容量判定；若保护物品导致无法腾出足够空间，返回明确阻碍及替代，不在“需要2格/已有1格可继续”之间循环。
- 玩家与伙伴先检查能力及原生进度归属。需要玩家首次收获触发任务时，保留至少一个合格作物给Farmer，伙伴收其余。
- 清理围绕主田区、道路、近期建设空间和材料缺口，按实际路径选附近混合障碍；预算要扣除当日/后续必要农务和生产，不把清图当经营目标。

### 5.3 日程示例（条件化，不写死每天同一表）

以“店9点开放、作物成熟、仍有待播地、体力充足”为例：

1. 早晨刷新天气、任务/邮件、成熟作物、库存、现金和设施状态；计算今天真正需要采购的种子及预算。
2. 伙伴处理适合它的收获/浇水；玩家完成需要原生身份的关键收获，读相关信件，准备出行包。
3. 开店前在已批准田区做可中断的准备工作；按路程倒推出发时刻，不反复试门，也不在门口空等数小时。
4. 一次进店完成合并采购，回固定田块播种；清理、布局、播种、浇水由同一个项目连续完成。
5. 下午在钓鱼、当前可进矿层、明确资源缺口、机器供料、解锁任务等可行方案中比较净收益、发展价值和成本；伙伴处理独立且有用途的劳动。
6. 产出及时进入库存与收入计划；依据周转需要决定正常销售或留料，不能刚收获就忘记可用资产，也不能为等晚间导致白天无钱却不比较直接出售路线。
7. 收工前检查全局而非仅脚边候选：经营计划剩余工作、近期窗口、可用补给、返程、风险。没有有价值可行工作可以休息；有条件继续却卡住必须标成异常，不能用“无候选”掩盖。

**不用完体力不必然错误，但连续剩170–205体力并伴随空转、早睡属于本轮明显失效。**优化目标是单位时间有价值产出和可持续发展，不是把体力条强行耗到0。

## 6. 结果、故障与失去进展

- 区分 `completed`、`partial_completed`、`waiting_until`、`needs_supply`、`recoverable_fault`、`blocked`、`cancelled`；不把所有未达数量都称为失败。
- 正常截止回传实际捕获/采集量、剩余量和下次可执行窗口；失败记忆不得因此把该地点列为不可用。
- 没有任何状态进展、没有子动作、却一直running时触发一次本地诊断；把“真在动画/钓鱼等待”和“容量规则空转”分开。诊断看实际阶段预期时长，不能用一个很短的统一超时误杀长动作。
- 无动作成功回执不能重置无进展保护；已经满足的材料目标不重新派任务。
- 抛竿air阶段的问题另做原生恢复审查：本轮部分失败从首个阶段就是air，疑似取消后的残留状态，根因未最终确认。应集中验证在抛竿、咬钩、小游戏、收鱼各阶段截止后，同一鱼竿当日/次日能正常再用。
- UI和日志显示当前目的、子步骤、停止原因、下次唤醒条件；不能只显示“执行中/思考中”。

| 阶段 | 改造内容 | 完成判据 |

旧I轮保留失败/人工停止记录，不与下一轮拼成七天。当前用户要求暂停，P1–P6均未执行，不自动恢复游戏。
