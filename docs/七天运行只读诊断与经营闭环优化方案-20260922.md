### 3.2 应怎样修

删除过时的“先启用才可选种”说明，统一工具说明与执行契约。不要添加“必须花掉 500 金”“每天买固定包数”“九点强制购物”等新配额。门禁开放也不等于柜台正在提供服务，仍保留原生现场核验。

### 4.1 首因是本地上下文，不是 DeepSeek 连续故障

[AutoplayModel.cs:33](/Users/zhongsuhua/.codex/worktrees/246c/星露谷agent开发/work/seven-day-diagnosis-20260922/source/AutoplayModel.cs:33) 在发送 HTTP 前打包：单请求总预算 30000，系统内容估算占 11167，留给上下文 **18833**。这些单位是本项目 `UTF-8 bytes / 2` 的估算，不是服务端 tokenizer 的精确 token 数。日预算 0 表示日用量不限，不表示单请求大小不限。

截面内共有 55 条运行侧 `model_request` 意图记录，但只有 42 次 `context_packed`；13 次本地超限没有发出真实请求。14 条 `model_unavailable` 中，13 条是上下文超限，另 1 条是春 4 日 07:20 的模型 JSON 格式错误（E3:476）。不能把这些统称为服务端网络不稳定。

### 4.2 恢复策略把局部故障升级成结束一天

### 4.3 应怎样修

错误按阶段分类：`local_context_pack`、`transport`、`response_schema`、`decision_apply`、`native_action`。确定性的本地打包错误先缩减至受界限约束的语义摘要，不反复提交同一超大输入，也不计入远端不可用次数。HTTP 暂态错误可有限退避；JSON 错误可用短反馈重试；容量、关店、目标鱼条件等只影响相关意图。
