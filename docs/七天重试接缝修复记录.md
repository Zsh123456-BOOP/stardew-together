# 七天重试接缝修复记录

依据：用户要求修复上一份七天报告列出的剩余问题，再重试七个完整游戏日。正常时间、Flash、单玩家、独立 AgentLab 起点；七天不是十四天闸门，不进入阶段 B。原生证据留在 `work/`。

## 实现与旁路核对

| 问题 | 本次改动 | 事实来源与边界 |
|---|---|---|
| 临时失败整天封锁 | 移除写入/读取 `Survival.Abandoned` 的第二套业务拒绝路径；访问失败统一进入条件记忆 | 保留原始原因和回执；门时间、所在地图、人物位置/睡眠、友好度、钥匙和阻挡变化后重新核验，原生拒绝仍有效 |
| 一步受阻挡住整批 | 原子提交失败返回具体步骤、原始错误、全部未提交步骤和 revision | 不偷偷删除依赖，也不声称其余步骤已排队；模型可以重提独立步骤。查询工具误放队列时明确指出该工具需先查询 |
| 买种误当已种 | 沿用上一轮并列种子库存、田里作物、排队播种事实；本轮集中核验第二批购买后的播种 | 不用总作物数证明新批次已经种完；不自动覆盖模型经营选择 |
| 镰刀过度保护 | 根据原生 Tree/FruitTree/HoeDirt 处理区分安全地物；保护区、可受损幼树、苔藓、可收作物仍保留限制 | 不改变原生攻击范围；无安全站位记录准确目标并跳过该目标，继续批次；不能把跳过算完成 |
| 社交移动/出口错误 | 同一 NPC 站位不每 500ms 重建路线；仍监控卡住、人物移动。NPC 接近不可达独立为 `npc_stand_unreachable` | 上一轮 Sebastian 的错误发生在接近 NPC，不是跨图出口；保留真实门禁，不开发清障寻路、不瞬移 |
| 思考卡顿 | 状态采集分成八段，在不同帧读取并冻结；角色/时间/库存/菜单/队列改变时整份重建 | 只传脱离游戏对象的 JSON 到后台；增加分段耗时日志，不能以实现完成宣称所有慢帧消失 |
| 目标材料混淆 | 仓储候选从统一原生配方表附目标 ID、材料、实有和缺口 | 箱子与鸡舍不再只靠邻近文本区分；不限制模型经营取舍，不保证模型永不误读 |
| 停止后窗口消失 | 监督器独立进程组；启动器持有原生 stdin，监督输入 EOF 不再关闭它 | 默认暂停保留现场；显式 `--exit-on-stop` 才自动关窗口。是否真正保留以进程与桥接快照验证 |

每项均核对：保护是否有旁路；同一事实是否出现矛盾来源；全局玩家状态是否满足不变量。没有关闭停止监控、清空失败记录凑验收、增加物资、改时间或直接写进度。
