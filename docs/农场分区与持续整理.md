# 农场分区与持续整理

## 目的与分工

让 Flash 知道农场哪里需要整理，并一次下达有边界的工作目标。程序读取真实对象、选择下一处目标、寻找站位、使用原生工具、拾取、存箱，再继续。模型不需要逐块提供坐标。

这部分复用项目已有 Farmer 执行器、寻路、背包预留/卸货、独立任务队列、原生存档和日志。没有另建一套移动系统，也没有通过删除地图对象模拟劳动。

## 已接入的接口

| 接口 | 用途 | 执行方式 |
|---|---|---|
| `farm.maintenance` | 分类计数、保留对象、预算和剩余工作；设置日常整理开关 | 默认只返回摘要；指定 `scope` 才返回最多 32 个详细目标 |
| `farm.zones` | 设置 crop、production、woodland、pasture、reserve 矩形区 | 验证地图边界、重叠和树木许可；一次替换完整列表 |
| `farm.cleanup` | 创建、暂停、恢复持久整理订单 | 同一个 request_id、同一策略幂等，不重复创建 |
| `work.run(goal=cleanup)` | 调度器内部的持续劳动 | 绑定已有 cleanup_id；同一任务连续规划，每段最多六个目标 |

示例：

```json
{
  "request_id": "spring-farm-tidy",
  "scopes": ["roads", "courtyard", "fields", "general"],
  "reserve_stamina": 30,
  "until": 1800,
  "daily_limit": 30
}
```

Flash 拿到的是按道路、院子、田地、普通区域及明确分区统计的杂草、树枝、石块、树木/幼树数量、估计体力和订单状态。树木数量不等于可清理数量；`routine_allowed` 明确区分。默认上下文和 `world.read` 都包含 `farm_cleanup`，不必每次再发一个查询请求。

`scopes` 指区域；`daily_limit` 是已核验目标动作数，不是掉落数量。体力是保守估算，真实工具等级、掉落、阻挡等仍以原生结果为准。

## 清理与保留规则

- 日常处理原生杂草、树枝和小石头。按真实可达路线先处理附近一片，道路/院子在同等路程下优先；不为凑同工具目标绕过身边杂草。
- 建筑、设备、箱子、活作物、果树、挂树液器的树和牧草不会被当作普通清理对象。
- woodland、pasture、reserve 及旧版保留区排除清理；普通采集选目标也遵守这些保留区。
- 普通成熟树和幼树默认保留。只有明确指定 crop/production 分区的 `allow_trees=true`，且清理订单包含 `remove_trees=true`，才允许移除该区普通树木。
- 整理杂草用单格原生斧头动作，避免镰刀范围扫到旁边牧草；代价计入体力预算。不是远程直接删杂草。
- crop 是可开辟用地区，不代表必须把整个矩形种满。production、woodland、pasture、reserve 从新田块候选中排除；原有住宅院子/道路硬约束继续有效。

## 调度、恢复与记忆

开启 `farm.business` 且日常整理开启时，建立 `daily-maintenance` 订单。在已有玩家农务、投资和明确队列之后领取短批次，不阻塞伙伴的独立队列。默认每日最多 30 个目标、18 点停止；30 体力只是安全底线，实际还叠加未完农务和生产余量。

手动订单先于日常订单。每批之后重新读取地图，已被玩家或伙伴清除的目标不会重复执行。满包沿用实际 output 箱卸货/必要扩容，再回到工作区。缺工具、不可达、材料或原生菜单阻碍会返回具体原因；有限重试之后保留剩余目标，请求重排，不无限调用模型。

分区、开关、订单范围、每日和累计进度随原生存档保存。同一天恢复不重置当日额度；下一天重置每日额度，保留累计结果。暂停时保留订单但停止动作。读档后按照实际地图重新核对，不把旧运行中的命令盲目重放。

普通批次不需要 Flash 选择下一个石头。Flash 仍可以调整经营方向、清理范围或新用地区；每日额度用完不等于当天应该睡觉。

## 日志与验收

### 连续劳动与实际拾取

旧版在每个目标后走到原格并固定等待 0.75 秒，既产生停顿，也可能漏掉树倒后散落在旁边的木材。“按工具凑三块”仍会跳过附近不同类型障碍，因此改用前沿 BFS：从当前位置找最近可达操作位，预测清除后腾出的地格，再选择下一处。最多六个邻近目标组成混合作业，自动换镐/斧头，受每日额度、体力、保护区和占用约束；操作位传给原生执行器，不再由另一套几何距离规则重新选择。

移动与挥工具期间允许游戏自然吸入物品。继续劳动前扫描附近真实掉落物；离开当前小片或批次结束时补捡。拾取使用原生 `Debris` 整组中心判断吸附范围，持续追踪已观察到的掉落组，直到它们真实消失。仅在物品实际处于原生吸附范围时等待它落袋；没有掉落则立即结束，不固定停顿。

拾取不修改吸附距离，不把物品直接塞进背包，不远程删除掉落物。满包返回存箱流程，随后回原位置补捡；不可达、拾取无进展分别返回明确错误。动作回执记录 `pickup_verified` 和拾取路段数量；核验附近可拾取物已清空后才完成。持久清理也扫描范围内旧的散落物，不因石头/树已经消失就忽略地上材料。

正常资源采集复用同一批次和拾取执行器。需要强调：`pickup_verified` 表示该次作业范围内没有剩余可拾取物，原生背包变化才是材料入账证据；掉落被其他角色取走、落水等情况不能被伪记为玩家收入。

结构化事件：`farm_zones`、`cleanup_requested`、`cleanup_dispatch`、`cleanup_progress`、`cleanup_complete`、`cleanup_error`。经营快照含清理摘要。原生子动作的路径、结果、消耗和掉落仍使用已有动作回执；不把订单目标数等同于收入或物品数量。

规则检查覆盖保留区、树木双重许可、日额度、跨日恢复和序列化。`scripts/check_farm_cleanup_native.py` 集中检查摘要、幂等、参数冲突、暂停、满包卸货、跨批次连续清理、边界牧草保护、授权幼树和成熟树原生砍伐。测试明确使用 AgentLab 夹具；测试物资不计为正常经营成绩。

## 明确边界

- 当前持久整理由 Farmer 执行；NPC 可以同时执行已有浇水、采矿、生产等任务。本功能没有声称实现两个角色共用清理订单。
- 道路和院子自动推导，田地依据已有作物和当前种植方案识别。林区、牧场和加工区支持明确划定；尚不是自动设计整座后期农场的求解器。
- 不承诺清空全图。未升级工具的大障碍、保护对象和不可达目标不会强行处理。
- 正常经营长期收益、跨季和后期产业仍须单独实测，不能用整理组合测试替代。

## 2026-09-20：问题 2、3 与经营预算的修复规格

### 2. 不再清几块就结束订单

1. `farm.cleanup` 保存持久订单；`work.run` 一次领取当天剩余额度，不再固定请求六个目标后终止。内部六目标路段继续复用寻路器，普通路段衔接只经过本地回执，无模型请求。
2. 同区域使用实际可达操作位的 BFS 距离排序，石头、树枝、杂草混排并自动换工具。保留区、占用目标、不足工具先排除；不用欧氏距离猜哪边能走。
3. 保存八格范围的工作片区中心。卸货后优先续接该片区；片区清完或失去可达前沿再选择新片区。原生步行和穿门，不加入瞬移。
4. 每段执行前重新读取地图、农务和预算。已有玩家生产队列到来时，完成当前段及拾取后让出执行权；不是强行抢断工具动画。每段最多六目标，因此让出不是逐帧即时抢占。
5. 完成判据为范围内无可清目标且无待捡物；日额度、体力或时间到限表示今天让出，订单继续保存。工具缺失、不可达、拾取停滞作为具体阻碍记录。

### 3. 砍倒与收齐分别记账

- 在原生劳动的每个更新周期读取实际 Debris，覆盖树木倒下、分裂、散落过程；新出现且靠近本段劳动的掉落组加入追踪。关联后不因移出最初扫描半径而丢失。
- 顺路由原生吸附拾取，远离当前片区或结束路段之前清扫；按游戏整组掉落中心寻找可达吸附位置。没有掉落时不固定等待。
- 暂停或拾取失败前，把实际剩余掉落坐标与原劳动位置合并保存；恢复/卸货后优先补捡。跨保护区散落的已关联物品允许拾取，但不会因此授权砍掉保护区对象。
- 连续五秒无吸附进展或无可达站位返回具体原因；保留未完成订单。不会删除掉落或直接生成背包物品来伪造成功。
- “已没有追踪掉落”与“玩家获得多少物资”分别核验。原生掉落可能被同伴拾取或落水；日志不能把所有消失都写成玩家收入。
- 掉落关联采用新对象、作业邻域和原生对象引用；不是游戏自带的精确因果 ID。相邻同伴同时产生掉落可能被一并捡起。读档后靠保存位置重扫，无法恢复原生未保存掉落的物品。

### 清理怎样与种地、生产共存

体力估算采用保守上界而非宣称精确最优：

```
农务预留 = 未浇的需水作物数 × 2 + 已提交计划中未播地格数 × 4
生产余量 = 最大体力 × 20%（向上取整）
当前保留 = max(15, 订单安全底线) + 农务预留 + 生产余量
整理可用 = min(当前体力 - 当前保留, 最大体力 × 35% - 当天已承诺清理成本)
```

- 只统计真实未浇作物、已提交播种计划，按地点/地格去重；浏览过但没提交的备选布局不会重复占用预算。
- 农场投资政策开启但还没生成播种队列时，按其允许扩种数与人工浇水上限的较小值先预留，防止早晨商店没开就把体力花掉。属于保守容量，不保证全部会播；投资完成或明确阻塞后释放这部分预留。
- 已有作物由 NPC 负责也先保留兜底体力，直到实际浇完才释放，不把“已分配”当成“已完成”。
- 所有清理订单共享每天 35% 最大体力的成本额度与 180 游戏分钟时长上限。费用在路段派发时保守扣账，中断不退款；吃东西、重试、新建订单不重置。第二天才重置。没有自动为清理吃掉生产补给。
- 待捡物可在停止新增清理后收尾；健康、过夜截止和暂停仍适用。用于播种的必要开地由种植技能执行，单独预留；这里限制的是额外整理，避免妨碍已批准种植。
- 普通砍木、采石生产订单仍遵循其自身资源预算；本次没有把全游戏所有劳动统一成上述上限。
- 清理让出后，由原有经营/日程调度执行浇水、种植、加工、采购、交付。清理返回不会直接发出睡觉指令。

例：270 最大/当前体力，15 株未浇、计划新播 15 格、安全底线 30：农务预留 90，生产预留 54，总保留 174；整理最多使用 94 点估算成本。若当前只剩 170，则停止新增清理，把体力留给农务。94 不是预期真实消耗，技能升级可能降低原生消耗。

### 日志与集中验收

`cleanup_route` 记录起点、顺序、站位、寻路耗时、实时 allowance、全日已承诺成本；`cleanup_yield` 记录让出的原因和预算。`farm.maintenance` 返回每张订单的实时 allowance，便于区分正常经营让出与故障发呆。

集中检查：混合目标近邻顺序 → 满包真实卸货 → 暂停续接 → 连续段无需 LLM → 成熟树/幼树 → 剩余掉落与实际木材 → 农务预留及跨订单共享上限 → 原有资源采集和规则田块播种/补水回归。原生组合检查使用隔离存档并明确记录夹具，不能冒充 Flash 自主经营成绩。


## 性能与队友接入补充

预算读取只访问农场/温室状态，禁止为了统计作物调用全地图可达性搜索。跨图先计算地图拓扑，再对实际候选出口做地格寻路；主线程分段耗时写入 slow_frame。

清理、普通 forage 与野生作物 harvest 由高层目标统一选择适当原生动作。NPC 远程野葱原生产物需进入其货袋，使用现有 OwnOutput 作用域修正缺省输出地图；玩家砍树仍走真实掉落吸附流程，两者不能混为“都已按玩家方式拾取”。

队友必须真实招募并列入 companions 才能分工；Selected 只是聊天目标。正常陪伴的 follow 状态不等于生产中，验收要求独立任务与实际货物证据。
