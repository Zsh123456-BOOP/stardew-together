# 同行 0.3：共同物资管理与经历检索

日期：2026-09-19。继承 0.2 的自主生活、共同农场、跨地图与保存能力，增加真实物资流转。完整设计仍在实施中，没有完成全部 P0–P6。

## 玩家能做什么

在普通箱子旁打开 F8 → 农场 →“切换附近箱子用途”。循环为：不使用 → 原料箱 → 收货箱 → 不使用。角色可以主动选择补料，也可以接受“给机器补料”“把随身材料存好”等指令。

- **原料箱**：允许伙伴取出一次加工所需的实际配料。没有被指定的箱子不会被取用。
- **补料**：先步行到箱子取料，再步行到机器投入。通过游戏原生机器接口消耗原料，使用真实加工时间；开始熔炼不等于已经得到铜锭。
- **随身物资**：属于指定角色，按存档和招募玩家隔离，存入游戏原生全局库存。途中取消、路线失败或者跨天，不会凭空消失。
- **收货箱**：伙伴走过去存放携带物品。满箱时物资留在身上；可以换空箱或继续原来的补料。
- **预留保护**：献祭项目中带品质条件的物品不会被补料消耗。目前采用保守方式：匹配预留条件的整类堆叠不参与加工，尚未实现精确分配后只使用富余数量。

“心事”可以查看携带物资。箱子用途随世界保存，未保存就退出会与游戏一起回退。

## 朋友式记忆的改进

聊天和自主决策会按当前话题检索实际经历。早先的钓鱼回忆可以在讨论钓鱼时被找回，不会必然被最近几次浇水挤掉。需求输入改为短摘要，不再把全部经历重复塞进需求字段。

这轮使用轻量关键词和时间排序，覆盖钓鱼、矿洞、农场、机器、物资、献祭、动物和休息；不是向量检索，也不是完整长期记忆系统。角色自己的劳动不能被模型改说成与玩家共同发生的经历。

## 本次实机证据

全部在专用 AgentLab 存档进行。

| 检查 | 结果 |
| --- | --- |
| 取料和补料 | NPC 从原料箱取出 5 铜矿石和 1 煤，步行到熔炉投入；来源箱剩余 5 铜矿石和 1 煤，玩家背包未被扣物品 |
| 原生加工 | 通过 `PlaceInMachine` 启动铜锭加工，回执记录 `processing_output`；没有直接发铜锭或清零机器加工时间 |
| 取消与存放 | 取出原料后取消，材料仍在 NPC 库存；分两次存入收货箱，总量保持不变 |
| 满箱 | 收货箱满时返回 `output_chest_full`，携带的铜矿石和煤不丢失 |
| 预留与授权 | 项目预留铜矿石时不生成补料候选；取消原料箱用途后也不生成取料候选 |
| 离屏与继续 | 玩家在 BusStop，伙伴在 Farm，使用之前已经携带的原料完成补料，无需再次取料 |
| 世界保存 | 专用存档春 9 日至春 10 日过夜，原生存档 XML 保留 NPC 库存里的 5 铜矿石和 1 煤；退出、重新启动并载入后，状态读取仍为相同数量 |
| 寻路修复 | 取料后的转弯曾被上游路径平滑带进机器格；改为沿已校验的路径节点行走，修复后实机补料通过 |

| 旧能力回归 | 指定角色挖矿/幂等/取消、浇水收获、动物机器检查再次通过；四图出行约 33.40 秒，海边实际钓鱼 10 秒，获得 1 件物品 |
| DeepSeek 指令闭环 | 玩家自然语言要求给空闲熔炉补一次料，DeepSeek 返回 `refill × 1`；真实任务完成数为 1、状态 fulfilled，物资回执确认实际消耗 |

## 仍然需要完成

- 箱子用途目前按邻近普通箱子设置；尚无完整区域编辑、物资包界面和精确品质分配器。
- 本轮验证的是普通熔炉。其他原版数据驱动机器复用同一接口，但未逐台实测；特殊派生机器、自定义机器与复杂配方仍需要适配。
- 收获和钓鱼仍使用既有 Squad 物品流；收机器仍进入玩家背包。尚未统一所有劳动产物到 NPC 个人库存。
- 播种、饲料投放、销售、购物预算、建设与季节依赖规划仍未完成。
- 矿洞楼梯/电梯、逐类任务归属、特殊订单、多天故事与关系变化仍未完成。
- 原型的关键词检索与固定个人心愿不足以证明长期“像朋友”；仍需完整多日玩法与真实玩家趣味验收。

当前运行仍是 Together 加适配 Squad。另外两个仓库没有作为独立运行 Mod 接入。
