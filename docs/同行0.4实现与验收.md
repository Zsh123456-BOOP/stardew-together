# 同行 0.4：实现与集中验收

日期：2026-09-19。环境：本机 macOS，Stardew Valley 1.6.15、SMAPI 4.5.2、固定版本的 The Stardew Squad。只在独立 AgentLab 存档验证，未使用个人存档。实际模型为 DeepSeek Flash。

按用户要求，先补齐实现，再进入一次集中验收阶段；这个阶段包含发现问题后的修复与针对性复查。保留失败记录，不把“首次全通过”当作既成事实。

## 修复过的实际问题

1. 商店柜台在该游戏版本使用 `Buy` / `OpenShop` 地图动作，需要按原生地图解释，不能只认旧名称。
2. 关门时进入失败是正确限制；采购用独立营业条件场景验证，未删除门禁来让测试通过。
3. 拒绝留下的约定卡曾阻止后续自主活动。现在拒绝不阻止角色继续生活，“停止”也清除未接受的提议。
4. 休息/生产等无 Squad 任务对象的活动，战斗结束后需要独立恢复记账，不能套用挖矿任务的恢复分支。
5. 普通角色查询不一定能找到暂存矿层中的伙伴；现在优先查受控队伍的真实角色引用。
6. 原生矿层清理只看玩家，会移除仍有队友的楼层。现在保留有人同行的实际矿层实例，离开后恢复正常清理。
7. 上游每天解散队伍，必须补长期同行的早晨恢复。只恢复控制权，不把角色传到玩家旁边。
8. 离屏住宅尚未填充门的运行字典；寻路直接读原生 Door 属性，允许 NPC 出自己的房间与经过公共门。
9. 已满收货箱不再生成无意义的存放候选；出售运送绑定实际拾取的物品实例。
10. 山路实际寻路需超过上游的 500 节点上限。受控队友改用优先队列与按地图大小限定的搜索；正常地图出口仍需亲自走到。
11. 钓位原先为多个水面反复运行寻路，会在地形复杂时卡顿。现在一次计算可达区域，供附近工作目标和钓位共用；候选短暂缓存，执行时仍逐格核对真实碰撞和目标。
12. 连续清理后，角色可能站在待翻地上。锄地候选按原生规则忽略角色和玩家占位，仍保留建筑、物品与地形检查；先走到邻格再挥工具。
13. 清除记忆同步清掉最近模型决定、未接受的提议与旧气泡，保留关系和当前工作。
14. 共同承诺和相处时间使用独立的幂等事件，防止一种关系更新遮掉另一种；过夜日记在计时任务检查点之后写入。

检查脚本也经过纠错：剧情暂停使用真正的原生事件；离屏矿层保留用独立休息保持角色在场，避免自动跟随离开导致测试对象错误；计时活动从运行层真实回执读取，而不是查询只登记外部请求的桥接命令表。人设对照隔离前一次经历，避免将记忆影响误判为性格失效。

追加集中检查覆盖了：矿洞入口和第一层往返、寻路修复后的动态障碍与播种、原生过夜出售收入、重新加载后的记忆与存档回滚，以及预热后的自主运行性能。

## 任务与成果归属

| 类型 | 可以承担的部分 | 完成证据与边界 |
| --- | --- | --- |
| 交物任务 | 准备、带回真实物品，陪同 | 玩家实际向正确 NPC 交正确物品；错误对象或物品不完成 |
| 资源收集 | 采集、运输、库存缺口提醒 | 库存与原生收集计数分别观察；以游戏实际回调为准 |
| 钓鱼任务/图鉴 | NPC 自己钓鱼并带回物品 | 不把持有一条鱼当作玩家亲自钓到；共同挑战分别记录双方成果 |
| 战斗 | 实际 NPC 战斗 | 上游原生伤害调用使用招募玩家为归属者，统计必须观察实际增加，不能另改完成标志 |
| 献祭/特殊订单 | 读条件、备料、保留品质数量 | 玩家进行专属提交；库存齐全只写“备齐”，不写“完成” |
| 制作/建设 | 已学配方或建设资金的准备 | 玩家制作与选址；制作项目观察加入计划后的原生制作计数增长 |
| 出售 | 把许可物品运入真实出货箱 | 当天不提前加钱，收入由游戏过夜结算 |

原生回调契约不是“真人玩完钓鱼小游戏”的录像。Steam 没有运行，因此不声称验证过 Steam 成就弹出；本轮观察的是游戏内任务与统计。

## 表现与性能

预热后测量 60 秒：两名受控队友，自主活动开启。Together 主线程 Update 共 3604 次，平均 **0.350 ms**、P95 **0.369 ms**、P99 **3.346 ms**、最大 **49.324 ms**，其中 23 次超过 16.667 ms。身体更新单独测量：最近 3600 个样本 P95 **0.124 ms**、最大 **12.572 ms**。身体样本是一次角色更新，不是两名角色的总帧耗时。

相同测量流程在共享可达区域优化前，Together P99 为 **88.160 ms**、最大 **210.265 ms**。这是场景观测，不是跨硬件基准；两次执行的随机活动不完全相同。数据不包含原版游戏及其他 Mod 的全部耗时，也不能凭局部 P95 宣称整局恒定 60 FPS。仍有偶发尖峰，未包装成“完全无卡顿”。

界面以 1280×720 检查。动作证据使用游戏真实帧，按文件记录的实际时间间隔编码，不加速；它是抽帧回放，不能用来推算游戏完整帧率。

## 验收解释

七天用例是压缩的连续活动和正常过夜保存，保留同一项目、作物、物资与关系；不是七次空睡，也不是七个完整时长的真人游玩日。不得用它替代长期趣味评价。

设计中的真人趣味评分需要真实玩家，尚不能凭自动用例或模型自己的回答给出评分。“足够像朋友、愿意长时间一起玩”是持续体验结论，代码和回执无法独立证明。

目前面向单人、普通农场及核心地图。特殊交通、所有扩展地图、多人与所有剧情分支不属于本轮适配承诺。清理只处理明确授权地块的杂草和树枝，不会自动砍装饰树或拆建筑。
