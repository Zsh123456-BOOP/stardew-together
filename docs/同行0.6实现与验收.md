# 同行 0.6：从共同心愿到真实备料

本版把“想得到某个东西”接到百科、持久化规划、伙伴聊天和自主行动。入口是聊天里的“我想要……”、百科条目的“加入计划”，以及经营页的“心愿与材料分工”。不是添加一个只会回答攻略的聊天入口。

## 已交付的闭环

1. 选择明确物品或制作配方；数量 1–99。模糊或重名目标打开百科供玩家选择。默认发现范围仍生效，可由玩家切换完整资料。
2. 读取当前加载的 `Data/CraftingRecipes`、简单确定性的 `Data/Machines` 和实际存档。当前原生测试环境解析出 150 个制作配方、32 条加工路径；不调用随机产物生成过程。
3. 用有界依赖图展开成品、中间材料和基础资源；已经持有的中间材料先抵扣，实际机器中的待收/加工产物单独计数。配方未解锁仍可准备材料。缺少加工设备时，不会为了普通材料隐式追加整套设备建造；可以直接收集或由玩家明确添加设备心愿。
4. 按旧共同项目优先、新心愿创建顺序分配库存。品质与类别需求共用库存账，避免同一堆物资重复满足多项目标。预留进入原有 Squad 保护机制，阻止被普通赠礼、出货或机器补料消耗。
5. 每一行可选玩家负责、一起准备，或与当前伙伴商量。LLM 结合人设、精力、关系和已有约定接受、协商或拒绝；拒绝后该步骤会暂时退出该伙伴的自主候选，避免刚拒绝就自动去做。明确强制可以覆盖意愿。
6. 已观察到的目标生成具体行动候选：识别的矿石采矿、地面物品采集、成熟作物收获、机器成品收取。候选携带目标物品；跨图先沿出口行走，到达后重新检查目标和路线。不会把普通石头的采矿动作当成“已经得到所需铜矿”。
7. 行动结果更新实际库存，再刷新缺口。一次操作成功不等于长期心愿完成。成品库存达到数量，或创建心愿后新增的原生制作计数达到数量，才确认完成。
8. 目标、逐项分工、直接收集替代路线、进度记录随存档保存。普通聊天、自主决策和百科条目共用这些信息。主动分享仍遵守安静/放假模式和原有频率。

## 使用示例

在完整资料模式找到 Keg（游戏中文时为酿酒桶），加入计划。配方未学会会显示原生耕种等级条件；材料会继续拆解为木材、铜/铁锭及其有设备支持的矿石加工准备、橡树树脂等。选铜矿石一行，点“商量交给伙伴”。当地图中存在对应目标时，伙伴可接受并开始真实采矿；玩家可以负责木材，或修改分工。

不喜欢某条制作路线时，选中材料点“此项改为直接收集”。这不会隐式创建购买清单、增加预算或解锁内容。点“暂停心愿”会释放预留并停止后续步骤；正在发生的单次动作可能已经产生实际收获，保留实际结果。

数量表示这份目标最后要备齐的总量，会计算已有库存，不表示“已有物品之外额外再得到这么多”。

## 明确边界

- 原生制作、解锁、设备放置、献祭/任务交付，以及消耗心愿预留材料的加工，目前仍由玩家操作；卡片显示条件与玩家步骤。已有普通补料只用未预留原料。本版没有新增自动合成、自动学配方或把预留原料交给任意机器消耗的能力。
- 复杂/随机机器输出、动态物品查询、额外条件及尚未适配的获取方式不生成确定性材料链。多个可用配方使用确定性默认选择；玩家可改为直接收集，尚无任意配方路线编辑器。
- 精准采矿仅识别已适配的原生矿石类型，不声称能自动取得所有矿物、木材或指定鱼。没有对应动作的材料仍显示缺口，可以由玩家分担；原有一般钓鱼、战斗和农务保留。
- 远处物资线索扫描有边界：已有出口能到达的前若干加载地图，每张地图限制条目数量；不是全世界、未生成矿层或所有箱子的穷尽搜索。真实路径仍以到达后的检查为准。
- LLM 是在有界事实和合法候选中表达、协商和选择；回复的证据、数量与部分明显承诺有检查，但不是对任意自然语言事实的形式化证明。错误时保留本地目标卡，不伪造执行结果。
- 未宣称验收所有内容 Mod、多人存档或长期真人趣味体验。本次实现解决愿望到可执行备料的连接，不等于拥有游戏所有操作能力。
- 本版不使用视觉、BM25、向量数据库或常驻 Python 服务。正式运行依赖仍是 Together + 本机单独准备的 Squad 适配版本。
