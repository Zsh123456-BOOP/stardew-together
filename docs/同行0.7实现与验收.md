# 同行 0.7：DeepSeek 自主工具循环与玩家控制

目标是让 DeepSeek 控制玩家 Farmer 与同行 NPC，通过原生操作推进存档，在此基础上保留朋友式陪伴。**本版本不能宣称已经自主通关或完成全成就。**

## 已实现的运行方式

F8 → 自主游玩 → 输入这份存档的目标 → 开始接管。F10、方向键或 Escape 可以把控制权交回玩家。打开同行面板也会先暂停接管。正式版是 C# Mod，不需要 Python 服务。

DeepSeek 可以连续调用状态、地图、库存、百科、原生进度和菜单工具；看到结果后再决定玩家与伙伴的行动。HTTP 请求在后台运行，游戏对象与实际动作只在游戏主线程访问。单项执行失败会阻塞其依赖并触发重规划；模型调用失败、预算耗尽或同一错误反复出现会明确暂停，不用本地规划冒充模型决策。

- `world.read`、`map.read`、`inventory.read`：实际地图、格子、物资、角色、作物和候选劳动目标。地图采用结构化格子信息与紧凑字符表，无截图识别。
- `knowledge.search/get`、`goal.requirements`：共用现有百科与实时条件；名称、别名与模糊搜索，不使用 BM25 或向量库。
- `progress.read/missing`：玩家原生任务、技能、制作、烹饪、出货、捕获、矿物与原生成就定义。平台成就仍需单独核验。
- `player.move/travel`：原生寻路，正常经过地图出口和建筑门。到达状态须实际匹配目的地。
- `player.work`：一次给出最多 36 个格子的翻土、播种、浇水或收获目标。程序逐格寻路，等待动画，并核验目标变化。
- `player.use_tool/interact/place`：工具操作、原生交互、种子或物品放置。原生礼物展示等动画要完成自身回调，不能因动作收尾被中断。
- `menu.read/open/choose/scroll/close`：读取原生 UI 组件、对话、配方、可售物品和库存；通过当前菜单 token 选择组件。过期菜单不能重放，手里拿着制作物品时不能直接关闭。
- `player.ship`：在真实出货箱旁将指定槽位物资交给原生出货系统；收入等待次日结算。
- `player.sleep`：从当前位置回家、走到实际床位、确认原生睡眠、处理普通出货确认、等待保存与下一日。普通技能升级确认走原生方法；职业二选一会明确报告输入适配尚未完成，不会跳过或伪造职业进度。
- `companion.assign`、`action.status/cancel`：复用 Squad 执行与回执。双方工作格有占用检查；交付前仍重验真实物资与目标。

玩家与伙伴是两类游戏角色。NPC 的劳动不自动等同于 Farmer 的捕获、经验、制作或平台成就。工具不直接修改成就完成标记、资金、日期或配方解锁。

## 正常时间与全天经营

游戏时间固定为原生速度。已移除额外时钟累加和倍率按钮，旧配置中的 `AutoplayClockRate` 值被忽略。控制动作、菜单、模型等待均不加速。

- `AutoplayDecisionDelayMs` 默认 250 毫秒，只控制收到动作结果后多久请求下一轮模型，不改变游戏时间。
- `AutoplayMaxCallsPerDay` 默认 180 次，每日预算不是预先消费次数。
- `day.read`：每轮决策自动提供今日农务、原生任务、共同心愿、目标库存和当前地图可达的工作候选。
- `day.plan`：模型保存优先事项和带用途的目标库存，跨日保留、按实际库存重新计算缺口；最近七天记录已核验动作批数。
- 程序对候选工作检查原生路径，按路线、移动速度与动作余量估算耗时/体力；保留体力 15 与返家时间。估算不是保证，遇到障碍或工具失败后必须重规划。
- `player.work` 支持连续农活，以及使用正确工具清理石块/树枝、拾取采集物；有限击打次数、体力底线、目标变化和原生动画核验。没有把所有资源操作都标为已支持。
- 睡觉需要说明原因。日间有可行工作/未完农务时要求重规划；体力耗尽且没有可行的免费采集，或进入晚间返家时段，允许休息。局部候选为空不代表世界上没有事做，提前睡觉仍需说明其他活动为何不可行。
- 模型仍负责选择事项与分工，程序不替模型自动选择所有活动，也不以修改日期或完成标记充当自主游玩。

候选覆盖当前地图最多 12 项可达的作物、石块、树枝、采集物；不等于全地图最优路线，也未包含钓鱼和所有商店/任务的自动调度。角色可使用现有地图、百科、菜单和伙伴工具继续探索和执行。完整的经营效率仍需多日试玩衡量。

## 记忆、暂停与保存

目标、工作计划、有界观察日志和真实执行计数随原生存档保存。重新载入后先暂停，点“开始 / 继续接管”再核对实际状态，避免重放尚未核验的动作。每次接管有独立运行标识；接管前的回执不是模型本轮劳动证明。

存档结构升级为 6；旧版 Together 会拒绝写入更高版本记录。游戏退出前尚未发生原生保存的当天行为，依旧遵循星露谷的读档语义。

## 验收记录

1. C# 规则检查：114 项通过，包括原有陪伴/目标/百科逻辑以及新增模型输出格式、旧倍率禁用与每日时间/体力预算、决策频率和保存数据检查。
2. 实机原生动作检查：20 项通过，覆盖批量翻土/播种/浇水、精确种子消耗、原生制作计数、物品转入实际背包、过期菜单拒绝、持物关闭拒绝、出货与次日收入、回家睡觉和保存换日。
3. 真实 DeepSeek Flash 闭环：已有百科/背包→正常睡觉→原生进度查询的单日验证。本次另做正常速度的白天经营观察，本次真实模型观察中，模型完成 2 格收获和 8 格浇水后，继续清理 12 处树枝，并给 Abigail 派挖矿任务。观察器只记录并在达到检查条件后暂停，不替模型选任务。这是有限时长的行为验证，不是完整一天或七天已通过。
4. 旧七日验收未通过：出现礼物动画打断、边界切换反复触发，以及旧倍率下等待过长引起昏倒。不能把日期差算作正常睡眠次数。已停用倍率并修复动作控制权，正常速度下 6 次房屋/农场往返通过；多日自主经营尚需继续验收。

5. 新增原生回归：9 项通过，覆盖旧倍率不生效、白天有工作时拒绝睡觉、12 处树枝对应 12 份木材实际入包、石块多次敲击、免费采集入包与目标库存缺口。清理后走到真实格子拾取，等待原生掉落结算和人物恢复，避免漏拾以及下一动作在人物仍不可操作时启动。

测试只使用 `AgentLab` 隔离存档，测试初始物资、场地及普通升级提示有明确 fixture 标记；种子从当前季节的原生作物数据选择，避免跨季重跑时误用过季种子。它不是从新游戏零准备开始的全成就证据。只读观察脚本不会替模型选择下一步。

证据保存在被 Git 忽略的 `work/autoplay-*.json/log` 与 `work/autoplay-observations/`。重跑入口：`scripts/check_autoplay_live.py`、`scripts/check_autoplay_transit.py`、`scripts/check_autoplay_resources.py`。真实模型观察使用 `scripts/check_autoplay_daily.py`（会使用配置的模型接口）；它会修改 AgentLab 的测试场地，不能用于个人游玩存档。
