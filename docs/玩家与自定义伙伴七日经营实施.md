# 玩家＋自定义 NPC：统一经营与七日验收

目标：DeepSeek Flash 控制真实 Farmer，协同项目创建的 Together_Partner（小禾），统一安排种植、采集、采购、畜牧、加工、扩产。正常时间，不将 NPC 当成第二个 Farmer，不招募原生村民作为必经步骤。

## 交付清单

- [ ] 自定义伙伴：内容定义、唯一身份、保存恢复、独立货袋、外观与人设配置。
- [ ] 伙伴能力与劳动预算：仅派已适配技能；原生进度任务归 Farmer；劳动点不冒充原生体力。
- [ ] 统一经营账本：实际现金/待结算/已承诺支出、可用库存/在途/预留、资产与施工。
- [ ] 双队列协作：必要农务、经营材料缺口、运回仓库；无伙伴时玩家承担必要劳动。
- [ ] 种植与加工：当季成熟、连片布局、照料容量、三类现金流候选、已安装加工能力约束。
- [ ] 畜牧/加工/扩建：复用既有业务链，补共享预算与断供恢复，不重复实现原生工具。
- [ ] 持续记忆与日志：复用记忆归档/压缩；保留未完成计划与实际回执；记录决策、成本和空闲原因。
- [ ] 集中规则与业务链测试，记录真实通过/失败，不将编译等同于运行通过。
- [ ] 正式七天：新建单人 AgentLab 存档＋自定义伙伴，从第1天早晨到第8天早晨，七次原生过夜；无人工救场，无资源/日期/完成标记修改。

## 原则与现有模块

复用 Together 的 PlayerExecutor、SemanticWork、FarmLayout、CropPortfolio、SeasonCashForecast、FarmBusinessRuntime、BusinessProduction、BusinessDevelopment、GoalPlanner、DailyAutomation、AgentSchedule、MemoryArchive、ContextCompression，以及 SquadAdapter 的寻路和劳动/货袋适配。

自定义伙伴先使用游戏自带人物的 sprite/portrait 素材引用，不替换该人物实例。自定义身份不计入原版完美度/介绍任务；人设存于既有 People 档案。外观配置明确说明素材来源，后续可独立替换资产。

NPC 已适配浇水、收获、野外采集、树枝/杂草清理、小石采矿、存货、抚摸。完整树木伐木、采购、制作、建造、菜单、任务进度归玩家；不把树枝采集标成完整伐木。伙伴按天记录自定义劳动点，运输与交接可在工作额度耗尽后收尾，正常次日恢复。

所有生产以真实物资为依据：在途货物减少重复采集需求，但交付前不可制作消费。已批准资产启动资金从种子可用现金中扣除。按原生机器配方估计已有机器的加工收益：容量、已有加工、燃料和时间共用，候选作物不各自复制机器容量。预测不可直接增加现金。

## 七日验收与日志

先集中检验开局与专门的中后期业务链，再用完全独立的新存档进行正式七天。专门夹具数据不进入正式验收。

只观察原生状态与日志，模型决定经营方向，确定性策略执行已启用经营政策。若需代码修改或人工补操作，该次失败，不拼接成功天数；保留失败日志并修复后重新开始。

每天汇总现金、收入、投入、库存、种植面积/照料、畜牧与机器资产、双方任务、等待原因、恢复、模型 token。费用仅依据真实用量与已验证价格计算，不能臆测。保持现有模型预算，不隐式提额；额度不足明确阻断验收。

七天只证明早期连续经营。后期畜牧与加工依赖专门业务链检查与后续自然发展，不以七天宣称已完成全游戏。
