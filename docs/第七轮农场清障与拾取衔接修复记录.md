# 第七轮：农场清障与拾取衔接

2026-09-22。本轮依据用户“修复完然后重新启动 7 天测试”的授权，将已成为真实阻断的农场清障提前实施。此授权不等于阶段 B 开放，也不豁免独立 14 天闸门。

## 根因

上一轮 `work/u6-trial-7days-2` 在春 1 11:50 停止，未完成一天。砍倒 Farm(70,23) 的树后，9 块木材散落到杂物围住的区域。原生移动只能通过可走节点；随后的采石和采木任务又将旧掉落拾取作为强制前置，连续三次 `pickup_unreachable`。没有改失败监控阈值。

## 实现（静态确认）

- `ClearanceRouting.cs`：纯算法比较行走与原生清障成本；缺少工具、受保护对象、体力不足、掉落容量不足均不能当作可穿越节点。沿单次原生行动最多清除三个挡路目标，防止导航变成无限清图。新域文件显式注册。
- `PlayerClearance.cs`：仅在农场支持普通石头（343/450）、树枝、已识别普通杂草。成熟树、幼树、巨石/树桩、建筑、作物、设备和未知对象不由导航擅自处理。原有明确伐木工具仍然可用。
- 沿已有控制器移动至相邻站位 → 原生 `BeginUsingTool` → 核验对象变化与真实碰撞解除 → 继续原路线。不删除地图对象、不瞬移、不直接入包。跨图清障绑定实际清障地图，而非整段 travel 的起始地图。
- 镰刀使用既有挥击几何与保护检查；执行前将实际扫及杂草的可能产物一并纳入容量模拟。稀有草帽、已解锁秘密纸条、夏季花种、特殊订单豆子、后期晶球计入相应预估。未知掉落类型不进入自动清障范围。
- `PlayerPickup.cs`：根据原生磁吸半径生成站位；允许通过清障抵达站位。仍依赖原生吸附，不改磁力、不注入拾取。
- 无法拾取时保留位置、物品、原因和条件，返回 `partial/pickup_deferred_conditions_unchanged`，不冒充完整成功。周围障碍、背包容量、工具、体力恢复或掉落位置改变后可重评；不因新命令或换日盲目重试。
- `SemanticWork` 与清理订单保留未拾取状态，但允许独立资源任务继续。清理区域有残留掉落时不能报全清完成。

接缝审查：直接移动、劳动站位、拾取站位与跨图移动复用相同 Walk 执行入口；清障后的每个节点仍用原生碰撞检查。纯规划不写真实库存。选择工具复用合法槽位入口；取消正在挥工具的清障等待原生落点结算。菜单、事件与地图变化不会在子状态中被吞掉。
