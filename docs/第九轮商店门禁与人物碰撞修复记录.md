# 第九轮：商店门禁、采购参数与人物碰撞

2026-09-22，承接用户营业时间与“反复撞人”截图反馈。上轮七天未通过，不拼接；此次集中修改后一次会话验证。

## 根因与实现

### 采购（原生日志＋静态确认）

第八轮原始模型请求为 `player.procure(location="Town", shop="SeedShop", ...)`。执行器在 Town 枚举柜台得到空列表，报 no_reachable_native_service_counter。它没有走 player.service 已有的参数校验，ServiceSubject 也只看 Town，因此 SeedShop 的原生门禁没有参与。不能把这次失败定性为“种子店柜台物理不可达”。

- 新的 `ProcurementServiceArgs` 同时供声明校验和执行器使用，采购服务明确为 shop。店内地图与商店不匹配时，在移动前返回 parameter_service_location_mismatch 和真实可选店址。
- `services.read`、world.read、每次决策快照直接给出原生地图门禁、当天关闭原因和复查时间；shop.sources 增加同源时间数据。服务参数/关闭回执附同源门禁信息。
- 已有队列 not_before 和执行前 ServiceWindow 校验保留，真实资金、现场报价、库存与柜台交互校验不绕过。
- 明确限制：门禁时间不等于柜台营业时间。例如 SeedShop 的原生入口是 09:00–21:00，不表示 21:00 前一直能购买。店员是否在场及商店开放条件仍由原生现场调用核验；不以门开着伪报可以买。

### 行走（原生实现＋运行证据）

`work/GameLocation.cs:2695` 的原生人物碰撞分支以 `!pathfinding` 为条件。旧 Passable 传 true，计划和下一格检查会忽略 NPC，但实际 MovePosition 会碰撞。失败样本在 Town(64,64) 反复重算原路线。截图对应问题成立。

- Passable 改为原生普通移动碰撞查询，skipCollisionEffects=true，检查不触发推人等副作用。路径预览、下一格核验和实际移动遵守同一人物碰撞规则。
- 控制器在真实像素前进一步前检查人物边界；有新进入路径的人先 Halt 短暂让行，仍阻挡再按当前地图重算，不继续顶人。原生速度、碰撞和移动保留。
- 原生 Utility.withinRadiusOfPlayer 使用相邻方格范围，支持斜角。社交停止条件与其一致，候选站位扩展为该范围内可站立位置；达到原生距离就停止导航并原生交谈。
- 记录人物、实际站位、选定交互站位、路径长度、动态阻挡及等待时长。npc_stand_blocked 的坐标改为显式整数数组，不再是空对象。
- 没有瞬移、移动 NPC、修改碰撞开关、伪造任务/好感或忽略真正失败。
