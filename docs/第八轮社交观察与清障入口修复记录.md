# 第八轮：社交观察、清障入口与目标复核

2026-09-22。按用户“修复这些问题，然后继续”实施；正常时间、Flash、单玩家。七天试玩不计入十四天闸门，停止规则不放宽。

## 修改与事实来源（静态确认）

1. 新增 `SocialObservation`，直接读取原生 `SocializeQuest.whoToGreet` 与 `friendshipData.TalkedToToday`。`progress.read`、日摘要、发展路线、世界任务明细、声明校验及社交执行器共享这些事实，不保存第二套完成名单。
2. 明确 `greet + quest_id` 工具契约。指定介绍对象已满足，或普通聊天当天已经完成时，返回 `already_satisfied` 及具体 `stop_reason`、原生剩余名单；`completed=0`，不写原生任务、关系或统计。不把整个介绍任务伪报完成。真实新对话经原生核验后才记执行器完成量。
3. 社交失败记忆的解除条件包含同一份社交事实及依据；不再只用任务整体 completed 标记判断其条件是否改变。
4. 清障计划绑定实际路径对象、地图与终点。只有 Farm 上算法明确选择的清障路径才能进入 `BeginClearance`；普通路线、镇上动态人物站位不再被解释成挖掘计划。路径起点不作为待挖目标。保留工具、容量、体力、保护范围和单路径清障数量检查。
5. 劳动在开始处理目标和到达站位后各读一次目标。已清除的杂物/牧草/枯苗不空挥、不增加 completed；走动中导航清障造成的目标变化也会被观察。真正挥击仍比较原生前后状态，不取消无效果检查。
6. 原生回执增加可选 `stop_reason`；统一信封在值为 null 时保留真实 error，不让新字段遮蔽失败原因。

接缝审查：直接工具、队列声明及原生执行入口复用社交判断；介绍名单只有原生来源。清障只接管自己产生的路径，跨地图普通导航保留原有动态碰撞和重规划。新增原生只读 `social_probe` 仍在 AgentLab 三重门禁内。未改 Squad 上游、原生库存或角色计数。
