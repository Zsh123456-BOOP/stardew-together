# 第四轮补修：异步动作与查询衔接

日期：2026-09-21。依据：第四轮交接及用户授权，明确的实现缺陷自行修复后重试；架构方向、G3 和 14 天闸门不调整。

## 修复范围

过去同一模型响应中的 `player.service → shop.read`，前者仅排队，后者立即读未打开的菜单。
现在由 `DecisionContinuation` 保留本轮剩余调用与前置任务 ID：

- 动作仍使用既有执行器、真实寻路与原生菜单。
- 后续查询等所有本轮已排前置动作的真实成功回执，才执行。
- 前置失败、取消、需要复核或丢失，返回 `decision_dependency_failed_replan`，剩余调用不执行。
- 已排计划的任务也计入依赖；`menu.choose` 启动的异步原生操作同样追踪。
- 玩家暂停清除未执行的尾部；换日重新观察，不盲目重放；需玩家分支决策的菜单回到决策流程。
- 等待期间推进底层任务，不对同一等待反复请求模型。`action.status`、取消与暂停不受查询等待限制。
- 仍保留商店真实开启、商品报价、容量、预算和材料保护检查。

反旁路检查：模型调用通过统一入口处理，直接动作 / plan.submit 创建的任务 / menu.choose 原生命令均追踪；没有改动原生库存、进度或玩家全局状态。
事实来源：只查既有 Schedule 的实际任务状态及原生命令回执，没有另外推测“已经到店”。
