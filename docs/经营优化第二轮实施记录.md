# 经营优化第二轮实施记录

本轮承接[四天开发运行复盘](四天开发运行复盘与优化结果.md)，集中处理重复失败、伙伴利用率、思考卡顿、收获后再投资。不是新的四天或七天验收。

## 已实现与核验

| 项目 | 改动 | 核验 |
| --- | --- | --- |
| 材料数量契约 | `count`始终表示新增数量，`stock_target`才是全队目标库存；经营中省略数量或传0时补批准项目缺口；无用途返回明确的规划条件 | 域检查覆盖已有库存、增量、目标已满足、项目缺口上限；原生检查验证条件解除 |
| 失败记忆 | 按材料政策、目标区域、货物容量、瞬时故障分条件；稳定阻碍不因改数量、措辞、无关体力变化或冷却时间结束而自动失效 | 原生测试：降低体力并换数量仍拦截；批准新材料项目后立即解除 |
| 记忆可见性 | 当天稳定约束优先进入模型摘要，附证据及解除规则；成功后清除对应语义失败；已知阻碍与未知执行故障分开处理 | 不再统一告诉模型“走动或体力变化即可重试” |
| 伙伴混合清理 | 伙伴可执行已有`cleanup_id`，连续选择片区内可达杂草、树枝和普通石块；共享清理额度、保留农务劳动点，满货袋走现有存储链 | 原生清完6个混合目标，回执记账6个，货袋真实获得产物，保护区不受影响，0模型调用 |
| 清理单之间的占用 | 正在执行的指定片区优先于宽泛的日常清理；同一清理单不能同时由两个语义执行器领取 | 集中测试发现玩家抢清伙伴后续目标，修复后重测通过 |
| 路径提示 | 复用Squad可达区域遍历的距离，提供短时缓存的`route_tiles`；伙伴优先同片区内路径较近的候选，不按工具类型把目标分散处理 | 属于规划提示；实际动作仍核验实时路径，不通过设置角色坐标执行 |
| 决策准备 | 常驻日计划不再为每个候选地块运行寻路；详细`day.read`仍可按需查询；主线程冻结JSON快照后后台压缩，减少压缩中的重复整树序列化 | 已构建并运行；性能数据见下节，不能据此宣称所有卡顿消失 |
| 投资准备 | 种植布局的访问锚点不再逐株运行路径搜索；地块遍历前一次核验角色占用；只对真实可用温室评估扩展，避免为寻找温室遍历所有地点路径 | 集中测试发现未解锁温室被误选，已补原生解锁检查 |
| 收获后再投资 | 成熟农作物先收获；腾地、现金到账或增加种子后重开已结束的计划，保留当天已用预算；主田重规划回到Farm，同日已读取报价不重复空访商店 | 原生收获3株→核价→支出180金→播种3株并浇水；额度200金、保底100金，0模型调用 |
| 剧情选项唤醒 | 待执行工作不能阻止当前剧情问题、命名或职业选择请求模型；将这类阻塞与普通空闲轮询分开 | 首次短程观察发现领养菜单停住；修复后Flash自主完成领养与命名，继续收获和伙伴浇水 |
| 暂停观察保护 | 观察器暂停时保留已有原生菜单，不能用调试面板替换并丢失原生回调；保存暂停面板返回结果 | 最后补充保护并重新构建；未将其计入前述原生27项用例 |

数量契约示例：当前有10木材、批准项目需要50木材，`count=5`最多新增5；`stock_target=30`补到30；`count=0`补剩余40。清理道路或田区走`farm.cleanup`，不需要虚构一个“需要更多木材”的生产目标。

本轮伙伴清理仍不负责砍整树、树桩或挖大型资源块。自动接手清理优先限于伙伴已在农场且具有可达候选的场景；这不等于已经实现跨地图全局最优分工。

## Flash真实短程复跑结果

从保留的原生春5早晨存档开始，正常时间、无资源夹具，使用现有Flash预算。修复后运行约181秒，游戏从06:00推进到08:10，应用9轮决策；因预设180秒观察上限结束，不是失败保护停机。

- 玩家自主处理领养与命名剧情，收获14株成熟作物；伙伴完成6株浇水。
- 伙伴采集完成4个目标后返回没有合格目标；模型后续识别该地区的失败条件，未立即重复相同请求。该任务仍记为部分完成伴随失败，不改写成完整成功。
- 钓鱼获得1件产物后，后续跨图遇到Town原生剧情，中断返回`event_interrupted_read_menu`。最后这段剧情未在本次时限内验证完成。
- 现金仍为1462金。短程观察不能证明收获后的实际回款与利润改善；再投资链的证据来自上文独立原生组合测试。
- 未过夜，原生存档文件哈希与观察前一致。这些白天操作记录在日志中，不冒充已经保存的经营成果。

真实复跑的10566帧中，Together更新P95为0.745ms、P99为3.816ms，最大653.519ms，39帧超过16.667ms。后台上下文压缩首次15.942ms，之后约2.1–7.1ms；这个后台耗时不等于阻塞游戏的时间。

**思考卡顿只完成部分优化，未完全修复。**首次启动时仍出现同一帧叠加调度、遥测、上下文组装和快照序列化的尖峰。下一步需要按实际`slow_frame.stages`拆开重复状态读取和分摊准备工作；不能以均值、P95或“模型异步调用”掩盖这一个明显停顿。后续还需验证全天伙伴利用率，以及部分采集完成后的就近接续策略。

收尾重新构建并重载原生春5存档；当前实验窗口停在春5 06:30、住宅内，AI已暂停，显示自主经营面板，没有原生剧情或进行中的玩家动作。原生4个存档文件哈希均与观察前一致，最终状态见`work/operating-followup-final-state.json`。没有继续运行四天，也没有后台模型请求继续消耗预算。

## 复跑方式

先启动独立实验运行目录，并在另外的AgentLab测试存档中执行：

```sh
python3 scripts/check_operating_followup.py work/新的测试目录
python3 scripts/check_operations_kernel.py work/新的营业测试目录
python3 scripts/check_shipping_capacity.py work/新的出货测试目录
```

下面脚本不注入资源，读取当前经营存档后启动有上限的Flash观察，结束后自动暂停。`performance_reset`只清空性能计数，不改变游戏进度：

```sh
python3 scripts/watch_operating_smoke.py --output work/新的观察目录 --seconds 180 --decisions 12
```

后续长程验证应继续检查：首次收获后的持续补种和回款、伙伴全天有效劳动比例、运输绕行、失败解除是否过早或过晚、决策准备及投资计算的尾部耗时。不能把本轮短程检查拼接成之前未通过的连续四天验收。
