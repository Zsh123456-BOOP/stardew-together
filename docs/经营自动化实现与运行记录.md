# 经营自动化实现与运行记录

目标：DeepSeek Flash 在原生速度下独立经营，逐步发展种植、畜牧和加工；以真实动作结果和存档验证，不以成就枚举或测试物资代替进展。

## 本批实现

- [x] `farm.business` 统一经营政策：日预算、周转金、动物/机器上限、饲料储备；复用独立角色队列与共享材料账本。
- [x] `farm.business_status` 读取现金、出货待结算、库存、在制品、施工、农务、失败原因与投资候选。
- [x] 维护 → 供料 → 收机器 → 投料 → 出售余量 → 扩产的持续调度；失败有冷却，采购未使用的预算根据原生回执释放。
- [x] 经营材料展开为共享目标：搬运、采集、可达矿层探索、原料加工、制作设施；未知配方仍需正常解锁，不能直接授予。
- [x] `player.procure` 真实进店、核价、购买、收取、关闭；`shop.sources` 只提供潜在卖方，不假定其营业或有货。
- [x] `player.acquire_animal` 真实到牧场、选兼容畜舍、命名并核验消费/动物；饲料储备、喂养、产品采收、采收工具采购纳入经营。
- [x] 机器投资比较使用实际原料与加工时间，保留一轮原料；安装树液器并按原生时间等待/收树液。未适配的随机/自定义加工估值不伪装成确定收益。
- [x] 已解锁温室进入种植排期；布局保护出口、已有设施和通道，洒水器优先覆盖手浇地块。作物选择继续使用已有季节、成熟期、现金与劳动容量算法。
- [x] `player.recruit_companion` 走到已知 NPC 身边，遵循招募规则后更新农务分工；不生成假伙伴。
- [x] 路线预览使用纯路径计算，避免原生控制器在无人地图上修改玩家位置。
- [x] 复用现有日/季摘要、失败记忆与可回查归档；模型只接收当前摘要，完整经营日志不重复塞入上下文。
- [x] 新增按存档、载入片段、运行片段、游戏日区分的 JSONL 日志；代码构建标识写入每行。

## 仍须以运行证据验收

这些实现不是“已从零经营到后期”的证明。主方案 E01–E06 的整体勾选必须等待完整业务链通过。

- [ ] 正常新存档连续经营：自己接取初始物资、种植/照料、产物出货、实际收款和再投资。
- [ ] 新开局通过真实收入建畜舍、购买动物、稳定供料并处理产品。
- [ ] 正常解锁加工配方和材料，建设并维持酿酒等生产线；不是直接给测试机器。
- [ ] 跨季与温室/经营解锁、读档续接验证。
- [ ] 与单一种植基线比较收益、闲置率、资金短缺和维护遗漏，验证“经营越来越好”。

## 调度与边界

Flash 决定发展方向、预算和重要取舍；程序决定具体站位、工具、补水、存货、喂养、投料和下一批已有工作。现有任务仍优先执行；不同角色独立推进。未知配方或未开放区域交给模型结合百科建立解锁目标，经营器不会伪造完成。

现金与待结算收入分开。自采材料有机会成本。动物估值扣除购入干草成本，机器按当前库存估计供给；这是可解释启发式，不能称全局最优。背包/工具升级等部分投资仍由模型通过已有工具安排，统一排序当前重点覆盖机器、洒水器、建筑和动物。

正式启动与观察：

```sh
python3 scripts/watch_farm_business.py --start --seconds 3600 --out work/farm-business-natural
```

观察器退出默认不暂停 AI；F10 可立即交回玩家控制。观察器不授予物资、不调整时间、不自动点击完成标记。只允许接管独立 AgentLab 存档。
