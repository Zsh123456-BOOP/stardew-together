# 经营自动化实现与运行记录

目标：DeepSeek Flash 在原生速度下独立经营，逐步发展种植、畜牧和加工；以真实动作结果和存档验证，不以成就枚举或测试物资代替进展。

## 本批实现

- [x] `farm.business` 统一经营政策：日预算、周转金、动物/机器上限、饲料储备；复用独立角色队列与共享材料账本。
- [x] `farm.business_status` 读取现金、出货待结算、库存、在制品、施工、农务、失败原因与投资候选。
- [x] 维护 → 供料 → 收机器 → 投料 → 出售余量 → 扩产的持续调度；失败有冷却，采购未使用的预算根据原生回执释放。
- [x] 经营材料展开为共享目标：搬运、采集、可达矿层探索、原料加工、制作设施；未知配方仍需正常解锁，不能直接授予。
- [x] `player.procure` 真实进店、核价、购买、收取、关闭；`shop.sources` 只提供潜在卖方，不假定其营业或有货。
- [x] `player.acquire_animal` 真实到牧场、选兼容畜舍、命名并核验消费/动物；饲料储备、喂养、产品采收、采收工具采购纳入经营。
- [x] 机器投资比较使用实际原料与加工时间，保留一轮原料；安装树液器并按原生时间等待/收树液。未适配的随机/自定义加工估值不伪装成确定收益。
- [x] 已解锁温室进入种植排期；布局保护出口、已有设施和通道，洒水器优先覆盖手浇地块。作物选择继续使用已有季节、成熟期、现金与劳动容量算法。
- [x] `player.recruit_companion` 走到已知 NPC 身边，遵循招募规则后更新农务分工；不生成假伙伴。
- [x] 路线预览使用纯路径计算，避免原生控制器在无人地图上修改玩家位置。
- [x] 复用现有日/季摘要、失败记忆与可回查归档；模型只接收当前摘要，完整经营日志不重复塞入上下文。
- [x] 新增按存档、载入片段、运行片段、游戏日区分的 JSONL 日志；代码构建标识写入每行。

## 仍须以运行证据验收

这些实现不是“已从零经营到后期”的证明。主方案 E01–E06 的整体勾选必须等待完整业务链通过。

- [ ] 正常新存档连续经营：自己接取初始物资、种植/照料、产物出货、实际收款和再投资。
- [ ] 新开局通过真实收入建畜舍、购买动物、稳定供料并处理产品。
- [ ] 正常解锁加工配方和材料，建设并维持酿酒等生产线；不是直接给测试机器。
- [ ] 跨季与温室/经营解锁、读档续接验证。
- [ ] 与单一种植基线比较收益、闲置率、资金短缺和维护遗漏，验证“经营越来越好”。

## 调度与边界

Flash 决定发展方向、预算和重要取舍；程序决定具体站位、工具、补水、存货、喂养、投料和下一批已有工作。现有任务仍优先执行；不同角色独立推进。未知配方或未开放区域交给模型结合百科建立解锁目标，经营器不会伪造完成。

现金与待结算收入分开。自采材料有机会成本。动物估值扣除购入干草成本，机器按当前库存估计供给；这是可解释启发式，不能称全局最优。背包/工具升级等部分投资仍由模型通过已有工具安排，统一排序当前重点覆盖机器、洒水器、建筑和动物。

正式启动与观察：

```sh
python3 scripts/watch_farm_business.py --start --fresh --seconds 3600 --out work/farm-business-natural
```

观察器退出默认不暂停 AI；F10 可立即交回玩家控制。观察器不授予物资、不调整时间、不自动点击完成标记。只允许接管独立 AgentLab 存档。

- `work/farm-business-natural/baseline.json`：启动时真实状态。
- `samples.jsonl` / `latest.json`：每十秒运行状态、任务与模型次数。
- `result.json`：观察时长、跨日次数、是否失联；不是成功验收标记。
- `work/CompanionMods/Together/logs/<save>/<epoch>/day-*.jsonl`：经营快照、模型/动作记录、预算与队列、成功/失败及每日结账。
- 原始动作的 `navigation`：目标格、实际格、剩余路径、控制器归属与等待秒数。

后续看日志先核对 save/epoch/run/build，再按失败原因统计；区分模型等待、走路、菜单、动画、机器等待与真正无任务。收入取原生已结算数；同一动作的 effects 与 native_progress_evidence 是同一证据的两个呈现，不能重复加总。

汇总指定存档的日志：

```sh
python3 scripts/summarize_farm_logs.py work/CompanionMods/Together/logs/<save>/<epoch> --out work/farm-business-natural/summary.json
```

`run-info.json` 保存实际存档、载入片段和日志目录。观察器退出时也会生成汇总，按任务去重，容忍最后一行写到一半的情况，不把缺失数据当作已验证的零调用。

## 2026-09-20 移动停顿与田块选址修复

用户指出：移动一卡一卡，未清完整片杂草就播种；测试画面里田地又放在了住宅门前。

定位出的不同问题：

1. 原先选地只接受现成空格，倾向离当前位置近的格子；逐格翻土→播种→浇水，缺少整田前置阶段。
2. 紧凑田块也不代表正确选址。仅保护门口一个交互点仍会把院子种满，必须先划禁种区域。
3. Farmer 借用原生 NPC 路径控制器时，中间路点会花一帧停止；采集每个目标走到掉落处等待后，结束还有一次重复的固定等待。
4. 修复前 Together 主线程记录出现约 348ms 峰值，但绝大多数更新不足 1ms。此指标不覆盖游戏和其他 Mod，不能把所有卡顿归因于一个原因。

已实现：

- [x] 手动 `farm.plan` 和经济组合共用紧凑矩形选地；地形/劳动容量不足时缩小面积，避免东一格西一格。
- [x] 区域内可清杂草、树枝、小石头纳入准备成本；保留已有作物、树木、设备和保护区。区域必须有实际可达入口，不清整张农场来假造通路。
- [x] 整个组合田块先清障，再批量翻土；随后各作物施肥、播种、浇水。保留原生动画、工具消耗、补水、背包恢复和失败核验。
- [x] 住宅整段正面留四行院子；建筑边缘留操作空间；从住宅前方到可达出口/设施规划服务道路，作为硬性禁种约束。温室沿用室内布局，不套住宅院子规则。
- [x] 路点衔接只合并零移动的中间帧，每帧仍至多一次原生移动；不改游戏时间、速度或碰撞。复用刚算出的站位路径，移除采集结束重复等待。
- [x] 动作增加 `navigation_summary`（寻路次数、寻路耗时、重试、有效执行时间），慢帧写入 `slow_frame`；限制日志频率。
- [ ] 完整农场总图：独立畜牧区、加工区、未来建筑预留、多季稳定田区与玩家编辑。当前院子/道路约束是基础，不宣称完整长期分区已完成。

验证：初版整田原生测试 9 项通过（明确使用测试物资），确认先清理/翻土再播种、15 格全部种植浇水、空壶自动补水、树和箱子保留。该轮测试田预设在屋前，不能作为农场选址成功的证据。新增院子/道路约束后，纯规则检查 184 项通过；最终原生结果见 `work/farm-bed-native/results.json`。正式存档与测试存档分开，不把赠送测试物资计入经营成绩。

### 相关 Mod 的实际算法与复用边界

- [Better Junimos CropMap](https://github.com/hawkfalcon/Stardew-Mods/blob/7128ddd2394d1fe3228f8f67cadaa0cf24413ee4/BetterJunimos/CropMap.cs)：围绕小屋存储每格作物类型；[PlantCropsAbility](https://github.com/hawkfalcon/Stardew-Mods/blob/7128ddd2394d1fe3228f8f67cadaa0cf24413ee4/BetterJunimos/Abilities/Base/PlantCropsAbility.cs) 在已有空耕地选合适种子。借鉴分区与逐格用途约束；它不是自动设计整座农场的求解器。没有把其直接赋值作物的实现替换本项目原生工具操作。
- [WaterBot](https://github.com/andyruwruw/stardew-valley-water-bot/tree/f7bbad4796a8b8289378429450395359860cd7e1)：读取网格、按邻接分组、A* 算组间代价、贪心遍历、BFS 找补水点。适合后续优化分区农务路线；其算法不负责选择新田块位置。此次保留已有寻路/补水，未整包迁移。
- [Tractor Mod](https://github.com/Pathoschild/StardewMods/blob/develop/TractorMod/docs/README.md)：按玩家驾驶范围和手持工具批量作业，布局由玩家决定；不以其无体力/无限水行为替代本项目原生经营验收。

本次是参考职责划分并复用项目已有原生执行器、经济算法；没有声称已整合上述三个 Mod 的源码。

分区回归中，旧测试预设区域被服务道路占用一边，程序正确缩减为 8 格；因此旧测试仍要求 15 格的断言失败。保留原证据于 `work/farm-bed-road-reservation-evidence/`。扩大测试允许区并让断言检查实际规划的完整田块，仍要求 15 格、原生种子消耗、清障先于翻土与播种，不通过删除道路规则迎合测试。新增洒水器中心留空的 8 格灌溉模块检查，避免矩形规则浪费灌溉覆盖。
