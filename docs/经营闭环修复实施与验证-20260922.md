## 实施内容

| 工作包 | 最终实现 |
| --- | --- |
| P0-1 观察与上下文 | `ObservationContract` 统一显式只读元数据，涵盖 business/capacity 和带 action 的生产查询。终态保留 requested/completed/remaining、原因及身份；异步报价保留真实 token、价格、成长与预算。待交付信封默认 4200 个项目估算 token，未装入的观察不被确认送达。大型字符串按 UTF-16 边界无损分片，空数组/对象保留。查询保留稳定归档索引，移出 32 条在线窗口后仍可用原 result_id 续读；沿原生存档游标校验时间线。 |
| P0-1 补读与压缩 | `ContextBudget` 拥有最终省略决策，不先套另一轮全文压缩。`context.read` 对所有省略 section 提供实际路由；`plan.read` 首屏不再嵌套完整回执字符串，完整回执由 action.status / query.read 取回。任务卡不复制整段模型计划。 |
| P0-2 失败恢复 | 区分本地打包、HTTP/超时、回复格式和决策应用。远端有限退避；一次格式错可反馈重试；确定性本地错误不累计远端失败、不切上午睡觉。无法恢复时，已启动的原生事务收尾后明确暂停并保持时钟；不会反复过夜冒充推进。删除局部六次错误直接睡觉路径，保留显式日预算、用户收工、夜间与致命保护。 |
| P0-3 生命周期与排程 | Schedule 统一 readiness，派发和占用共用，未来 sequence_after 链不再占住空闲角色。Finish 回调统一捕获服务预检、声明拒绝、依赖/截止、partial、原生完成及取消。取消记录恢复、政策、项目、模型或外部请求的来源。睡前依据包含现金、体力、库存、天气及进展。 |
| P1-1 报价与再投资 | 原生开店比较表主动加入观察；有效报价独立于自动流程阶段产生选种机会；移除隐藏的二次启用说明。暂缓采购保留具体理由与事实基础，现金、库存、作物、工具、窗口变化后可重新评估。现货仍需原生核价和执行。 |
| P1-2 会计与工具 | 原生费用按 command/effect 幂等入账，金币、商店货币、交换材料、核桃分开。待办预算减已证实消费；同一发展项目的静态预留与已排承诺合并；未核验回执的资金单独保留。删除以余额差猜采购支出的路径。奶桶/剪刀识别共享箱；种植根据实际地块派生工具，已湿净地无需斧、锄头或水壶，干地仍需水壶。 |
| P1-3 机会与依赖 | 空 farm.business 查询不改变策略。生产建议分页，缺料准备方向及原生依赖可查；动态/随机/多输出规则显示 valuation_unknown，不捏造收益。饲料显示库存、保守可维持天数及服务窗口。生长期共用原生地点、跨季、职业、已观察肥料/稻田条件；每格及数量仍由实际布局校验。自动投资的 15:00 截断改为服务、剩余劳动与返程可行性。去掉全日钓鱼行业禁令和业务固定重试冷却，沿条件记忆重评。 |
| P1-4 性能 | 失败回执不再逐次重扫全部机会、NPC 和容量选项，改指向下一份新鲜快照与显式查询。增加 preparation、receipts、services、readiness_routes、preflight、kit、admission、native_dispatch 排程分段测量。原生对象仍只在游戏线程访问。 |
| P2 证据工具 | `report_operating_loop.py` 按原始日志生成逐日现金、真实支出、待结算估值、劳作/运输/等待、睡觉来源、候选选择、查询/终态交付延迟、失败解除与慢帧证据，支持 run_id 过滤。完整再投资闭环仍需逐段连接证据，报告不会自动授予 G3/G4 或十四天通过。 |

## 验证

最终域检查 **520 项通过**，Python **17 项通过**。Together Release 编译成功，0 警告、0 错误；不部署到原运行目录。macOS 上故障退出的旧域测试会锁住 PDB，因此域验证使用独立输出目录、关闭 apphost 和符号，并直接执行 DLL；未清理用户的其他进程。

历史固定截面重放：

- 46 份真实模型请求，打包失败 **0**。累计项目估算大小由 517647 降至 484473；这是 UTF-8 字节除二估算，不能当作实际账单节省。
- 50 份原始查询，包括 59966 字符的 plan.read；生成 455 页，最大页 **1992** 个估算 token，全部积压分 7 批交付。
- 域断言额外验证巨型转义/中文/emoji 字符串完整拼回、空容器不丢失、0/5 与 2/5 partial 保留、归档查询身份/时间线、未来排程、真实依赖与顺序依赖差异、幂等终态、现金货币分离等。

原生完整组合 **8/8 通过**（`work/operating-loop-verified-native/result.json`）：

1. 六个查询交付真实模型。
2. 运行时经营契约检查（此轮 28 项）。
3. 非法起点明确拒绝、旧控制器不跨图改坐标、合法道路原生返家。
4. 同条件空种植方案失败合并。
5. 混合种子实际种植、浇水。
6. 已知箱子配方原生制作。
7. 原生报价 → 模型选择 2 包花椰菜种子 → 原生支付 **160 金** → 真实种植浇水；原生消费账增量与报价一致。
8. 显式收工、不强制出货、原生过夜保存；日记准确跨日。

终态 2/5 的人工注入属于运行时接线检查，不是本轮钓鱼产出实证；该夹具有 EnableLab、WorldReady、AgentLab 三重门禁，人工日期/地块/工具状态在探针结束时恢复。夹具的跳时日不能作为长期劳动比例基线。旧 Town 异常像素姿态仍未复现，不能把合法道路返家写成旧异常现场自然脱困。

最后调整钓鱼参数错误分类后，另跑 `--contracts-only` 验证当前构建，2/2 组合及内部 29 项接线断言全部通过；详细结果留在 `work/operating-loop-contracts-final/`。原生接线检查包括真实周三门禁与终态/约束学习、15 个补读入口、仓库工具、地块工具需求、本地错误不睡觉/不取消/不计远端失败、在线窗口移除后的归档查询补读。

性能：完整组合日最大 **321.151ms**，p99 **1.399ms**，超过 16.667ms **13 帧**；schedule 最大 **320.417ms**，其中 native_dispatch **317.633ms**。本场景最长阶段为睡觉原生派发。原长跑春 4 的 2120ms 与本夹具负载不同，不能据此报同场景加速倍数，秒级长跑尖峰是否彻底消失仍待新基线验证。
