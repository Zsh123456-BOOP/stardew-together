| 获取适配 | 普通材料获取映射移到原生资源适配层；有树枝时先提交其实际数量范围内的前缀，之后重读缺口 | 原生连续收集 50 木材通过；不代表树木拾取故障已修复 |
| 执行连续性 | 执行器/队列忙时不因普通空闲事件请求模型；异步回复校验队列版本；进行中任务不因普通模型取消而中断 | 原生整组通过；Flash 一次决策提出并启动，后续采集与制作由程序连续完成 |
| 条件恢复 | 普通失败保留目标与真实剩余量；相同条件不再每隔一小时重发；任务完成立即唤醒依赖执行 | 原生失败后保留剩余 39 木材；不报目标完成 |
| 候选与展示 | 可选拾荒只推荐当前地图、短可达路线、容量合适且有用途的物品；面板显示真实目标缺口，继续保留滚轮 | 编译；与正常经营竞争的完整基线尚未运行 |

能力通用是指：新配方使用已适配机制时，不增加“物品名→专用流程”。并不表示任意 Mod 的自定义回调已经能执行。原生 `Object.placementAction` 把特定物品转成 Chest 的机制映射仍保留在适配器；递归求解器不识别箱子、火把等物品 ID。

## 验收边界和仍需观察的事项

- 方案整体尚未全部验收。多输入类别的联合匹配、完整类型化效果契约、每种获取机制的统一成本比较、后台/分片求解，以及旧存档暂停重载等组合覆盖仍有缺口；不得把本次两类制作链通过勾为 P0–P6 全部完成。
- 普通配方通用执行与“从零自主经营好”是不同结论。基线只有用户再次明确要求后才启动。
- 复杂机器、随机产出、没有启动资源的循环、未知机制与建筑整备不默认为可执行。
- 当前路线比较首先利用库存与批次成本，再在执行入口检查真实工具、体力、路线、容量；不是跨季经营的全局优化器。
- 旧的箱子原生执行入口保留兼容；单玩家自主运行中的扩容前置交给普通目标。腾格解析器仍一层，不递归采集扩容。
- 多箱整备、建造材料及部分交付继续在转移前声明拒绝；没有提前开放阶段 B。
- 砍树后的 `pickup_unreachable` 需要独立定位原生掉落与可达站位，保留全部失败证据，不能用“树枝能捡”替代。
- 尚不将新建存档“无伙伴”验证视为旧伙伴库存保存/恢复通过。

## 运行方式

```sh
python3 scripts/build_companion.py --mods-dir work/GenericMods
work/dotnet/dotnet build tests/Together.DomainChecks.csproj -o work/generic-domain/bin
work/dotnet/dotnet work/generic-domain/bin/Together.DomainChecks.dll
python3 scripts/check_generic_goals.py --output work/唯一新目录 --flash
# 只复查模型目标接口，不重跑仓储链
python3 scripts/check_generic_goals.py --output work/另一个新目录 --model-only
```

采用独立域检查输出目录：旧目录存在系统阻塞的历史测试进程，直接 `dotnet run` 可能启动旧路径。没有终止无关历史进程；本次直接运行新构建 DLL，检查退出码。

组合脚本通过 AgentLab 原生新档开始，正常时间，不改经验、钱、配方或材料。所有步骤同一游戏会话执行；失败记录与成功记录分开，任何重启都不计作连续基线。
