# 阶段 A：连续存活实施与验收报告

本阶段仅针对失败恢复、夜间守护、模型不可用降级、原生检查点恢复。阶段 B 未开始。阶段 0 已通过，见《双身体阶段0穿刺报告》，提交 `8395219`。

## 1. 范围与证据纪律

- 仅在隔离 Mods 与新建 AgentLab 存档执行，正常游戏时间。
- 不写 Farmer 的经验、配方、成就、金钱、统计或完成标记。
- 本轮劳动由玩家 Farmer 执行；小禾保留可见身体与陪伴。旧 Squad 收获中的经验转记尚未迁移，不纳入本轮能力证明。
- 故障注入与恢复测试独立于正式连续验收；任何重启都不能拼成 14 天通过。
- 编译、域检查证明契约；原生日志才证明动作、保存和换日。

## 2. 已实现内容（代码；长程效果仍需验收）

| 项目 | 实现 | 边界 |
|---|---|---|
| 局部失败 | 当前目标记入当日放弃集，队列其他目标继续；沿用条件记忆 | 次日可重试，不把失败说成成功 |
| 反复失败 | 同角色同错误无有效进展累计 6 次，取消剩余计划并安全返家 | 等待工具原生击打收尾；不直接跳转日期 |
| 模型不可用 | 连续 3 次异常进入程序农务，照料结束后原生过夜；次日再试 | 不提高 token 或调用额度；失败原因进入日志 |
| 夜间守护 | 22:00 后无可执行玩家计划，直接返家睡觉 | 绕过经营价值争论，保留执行器的原生站位、菜单和保存检查 |
| 日常降级 | 复用 day.routine 收获、浇水、喂养、抚摸和收产 | 无自动新投资；次日恢复降级前政策 |
| 夜间菜单 | 原有确认保留，降级时按既有职业政策或第一个真实选项选择职业 | 不直接改 professions 或经验 |
| 自动恢复 | 原生存档保留运行意图，重载后撤销旧坐标/菜单任务，重新读世界规划 | 不重放旧回执；暂停会撤销独立恢复授权，避免旧存档重新接管 |
| 监督进程 | 只管理自己启动的隔离进程；异常退出自动加载同一 AgentLab 原生检查点 | 同检查点连续 3 次崩溃停止；正常关闭不当崩溃重启 |
| 原生保存证据 | Saved 事件 + 日期 + 原生存档文件哈希 + 当前运行 ID | 不用 SleepDays 单一计数替代保存证据 |

### 运行状态

`model → routine → sleep → 原生保存 → model`。局部异常不会立即停全场。世界一致性、物品守恒、日志、保存异常保留真停机；返家连续 3 次失败按用户停止规则停机报告。F10、方向键、界面暂停始终有效。

### 日志

`survival_transition`、`local_failure`、`model_unavailable`、`survival_sleep_started/result`、`native_saved`、`survival_new_day`、`native_checkpoint_resumed` 写入存档对应的业务日志。监督器另存进程代次、原生文件哈希、每 5 秒位置/体力/菜单/任务/模型等待、每日检查点快照。所有原始证据在 `work/`，不进 Git。

## 4. 长程结论

第一轮已中止，未通过：`work/survival-14days-1/result.json`，只保存了 2 天，墙钟约 723 秒。发现自动清理重提已放弃目标，拒绝被误算为新失败，触发过早收工。修复：在计划入口拒绝当日已放弃目标，沿用条件未变化的等待分类，拒绝不再累计原生执行失败。原始记录保留，不与后续轮次拼接。

第二轮已按用户要求停止：`work/survival-14days-2/result.json` 为 `passed=false`，停止码 `RuntimeError:lab_pause`；该次暂停由用户停工指令触发，不是崩溃。运行 ID `a3ee5d2d50fb4555b8b3713db08acef8`，AgentLab 存档 `449635135`。监督器已退出，自启动游戏进入其退出清理流程，未触碰用户其他游戏进程。

- **实测**：连续 10 次原生过夜及保存，检查点 `day-1-checkpoint.json` 至 `day-10-checkpoint.json`，重启 0 次；停在春 11 日 06:00。墙钟 2526.98 秒，约 42.1 分钟。游戏时间正常，天数推进快是多日过早睡觉，不能解释为经营效率高。
- **实测**：停止后 `Status=paused`、`AutoResume=false`、`SleepDays=10`、`Decisions=147`、现金 500、体力 270。完整停止前后快照见 `user-stop-before.json` / `user-stop-after.json`。
- **实测**：按运行 ID 汇总模型用量日志共 164 条，输入 1,415,170 token，输出 52,925 token，合计 1,468,095；其中缓存命中输入 371,840。用量记录条数与有效决策计数不同，不能混为一项。
- **实测**：初期确有播种 15 株、照料、取得鱼竿、采木等活动；但后续容量问题反复阻断，春 5、6、8、9 日在 06:30–06:40 就进入睡眠降级。现金没有净增长；这不等于资产总值没有变化，但也不能声称经营成功。
- **静态确认＋实测错误码**：`PlayerProduction.cs:54` 在材料消耗前检查输出容量；`StorageExpansion.cs:63` 直接要求空格。实际出现满 12 格、其中木材恰好 50 的背包，仍被造箱前置检查拦截。材料消耗后是否能入包应做原生链复验，当前没有修复。
- **实测**：九天的局部失败降级中，前两天原因是无指定仓储或扩容预算，之后七天是制作箱子要求空格；另一天因三次模型不可用进入日常降级。重复睡觉让流程存活，却未解除库存根因。跨日条件记忆与恢复策略需要重新设计。
- **待验证**：22:00 夜间守护自然触发、未知菜单恢复、完整 14 天，以及解决库存后能否持续完成经营工作。

`survival_transition` 等部分事件存在相邻重复写入（归档镜像与直接业务日志各写一次）；分析要按同日、时间、种类及 payload 去重，不能把重复日志当重复动作。此问题尚未修改。
