# 高层劳动、背包续作与 Flash 费用控制

2026-09-19。开发版 Together 0.7，正常游戏时间，仅 AgentLab 做破坏性夹具测试。

## 职责

DeepSeek 决定目标、数量、地点和分工。程序负责选目标、工具、相邻站位、原生路径、动作时序、体力余量、补水、卸货、结果核验。一次任务内的子动作不需要模型回调。

```json
{"tool":"work.run","args":{"actor_id":"player","goal":"wood","count":30,"location":"Farm"}}
```

`actor_id` 也可以使用实际招募伙伴 ID。不是创建另一个玩家；NPC 与 Farmer 的能力和原生进度归属仍不同。

| goal | 语义与当前范围 |
|---|---|
| stone / wood / fiber | 本次实际新增材料数量；木材目前限树枝，不含所有树木 |
| water | 找未浇水活苗；自动选水壶、缺水补水、返回继续 |
| refill | 自动找当前地图可达水源，走近并原生使用水壶 |
| harvest / forage | 采收或拾取多个真实目标 |
| clear_dead | 镰刀清枯苗，不伤活苗；当前限 Farmer |
| store | 去农场已有 output 箱存放可存物资 |

材料 count 默认 20。其它劳动 count=0 表示清完本地图符合条件目标，正数表示目标数量。默认保留 20 体力，22 点停止；可提高保留体力/提前截止时间。NPC 没有 Farmer 的原生体力条，不伪造共享体力值；按实际能力、货物、时间和战斗状态限制。NPC 木材/杂草劳动还受指定耕作区域策略限制。

队列支持高层任务的独立角色通道；一个任务拥有角色直到结束/取消。每个子动作之后重新观察，已不存在目标不会重复执行，不可达目标本轮排除。达到目标才 `succeeded`；体力/时间/容量/能力限制导致部分完成则保留实际 gained/completed，返回明确 stop_reason。最多 128 次子动作或 10 分钟后交回模型重新安排，不无期限占用角色。存档重载后保留待核验计划，不盲目重放内存子动作。

## 背包与储存

玩家采集前尽量留两个空槽。容量不足就暂存任务、走到农场指定 output 箱、使用原生 Chest.addItem 的叠堆/容量规则入箱，再返回原工作地点。只扣除箱子实际接受的数量，不复制、删除、出售物品。工具、种子、可放置设备、任务物品、已声明预留及少量食物保留。

伙伴用既有 deposit 动作走到 output 箱，更新真实货物后继续原目标；保留工具、种子、任务物品、预留及补给。没有可用指定箱、箱满、不可达或背包全为受保护物品时，返回原因，由模型规划解决；不会偷偷创建箱子或丢弃东西。

`inventory_plan` 给出玩家空槽、可存物、箱子位置/容量和保留政策。尚不是完整跨季库存优化，也未自动封装箱子制作/扩容。

修复 NPC 石料归属：原生普通石料来自 `Game1.createDebris(14,...)`，此前只处理 object/item debris，所以会“敲掉但未进伙伴包”。现在只在被控制 NPC 的输出作用域内捕获实际石料数量，视觉碎屑和玩家掉落不受影响。

暂停提示不再把中文交给英文游戏的像素字体，而使用 Together 的 zh-CN 字体；已用游戏 HUD 截图检查。

## 模型与费用

按用户最新要求，默认模型与隔离运行配置恢复 `deepseek-flash`，不自动升级 Pro。

官方价格 2026-09-19 核对，每百万 token，美元：

| 项目 | Flash 闲时/忙时 | Pro 闲时/忙时 |
|---|---:|---:|
| 输入缓存命中 | 0.003 / 0.006 | 0.022 / 0.044 |
| 输入缓存未命中 | 0.15 / 0.30 | 0.66 / 1.32 |
| 输出 | 0.60 / 1.20 | 1.98 / 3.96 |

来源：[DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)。不能拿旧集成示例中的静态价格代替现行计费页。

Pro 观察片段约 388 秒做了 62 次决策，运行至游戏 18:10 后因用户 F10 暂停，0 次正常跨日；不是两天自主经营通过证据。单条工具回传接近 1.6 万字符，原先还重复加入任务初始快照和完整回执。不能把字符数当 token，也不能凭旧总 token 数还原账单。

目前减少调用的方式：

- 常见劳动在程序中连续执行，目标完成/失败/中断才重新规划。
- 固定工具说明放在固定 system 内容中，避免混在先变化的状态之后；缓存是否命中仍以 API 返回为准。
- 双角色都已有待执行/执行中任务时，普通状态查询不触发新一轮付费轮询；空闲角色、错误、知识查询等仍唤醒决策。
- 重复状态查询只保留最新一份，避免同一 world.read 越查上下文越长。
- 当前计划保留，最近已完成动作使用摘要，完整证据本地保留并可按需查询。
- 不重复携带 task_started 的完整背包；查询结果和错误保留，不能为了缩短上下文抹掉失败。
- 每次自主调用记录请求模型、返回模型、输入/输出/缓存命中/总 token、延迟和 run_id，写入本地忽略目录 `Together/usage/autoplay-model-usage.jsonl`，不含 API Key。

这些改动减少重复上下文，不是删掉长期关系记忆；是否影响长任务连续性仍需后续长时间观察。

## 验收记录

122 项纯规则检查通过；10 项实机组合回归通过；中文 HUD 已截图确认无乱码。第一轮 Flash 实际调用完成同批三目标，用 7 次决策，输入 121078 / 输出 1567 token；按当日官方闲时价约 0.01656 美元，仅是该片段估算，不是账户账单。随后修复普通进度查询引发的付费轮询，并使用同批工作复核。功能脚本为 `scripts/check_semantic_work.py`，包括连续采集、空壶续浇、双角色、体力限制、角色所有权、满包存货和继续原目标。

这轮只验证劳动粒度、补给、储存与模型调用，不是全成就或完整游戏玩法通过。

最终 Flash 复核：三个既定目标全部完成，耗时约 51.9 秒，6 次模型决策，输入 61171 / 输出 991 / 缓存命中 14592 token，按当日官方闲时价估算约 0.00763 美元。输入量比第一轮同批工作下降约 49.5%，但这是单次片段对比，不是稳定节省比例或全天费用预测。仍存在中途多次查看进度，不能说已经最省。

中间一次复核触及 8 次调用限制，木材仅完成 10/12 后由测试器取消；如实保留在 `work/semantic-flash-poll-fix-limited.json`，不能计为通过。最终记录在 `work/semantic-flash-result.json`，功能组合记录在 `work/semantic-checks.json`。

实测最终成果：Farmer 原生浇水 6 株、自动补水 1 次、实际收集木材 12；Abigail 实际收集石料 3。测试后已暂停接管，未留下持续付费观察器。本轮没有验证两次自然跨日，也没有通过全成就。
